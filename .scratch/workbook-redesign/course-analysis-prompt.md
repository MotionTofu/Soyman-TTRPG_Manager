## Что уже есть в приложении

Не предлагай заново то, что здесь уже есть. Сопоставляй с этим.

- **Кампания.** Профиль, препродакшен, игроки и их персонажи, календарь кампании с внутриигровым временем, важные даты.
- **Сессия.**
  - Лента записей Мастера по ходу игры: время реальное и внутриигровое, @упоминания. После игры — «Проставить упоминания».
  - Запланированные сцены, журнал запусков сцен, явка.
- **Приключение → главы → сцены-узлы.**
  - У узла есть тип (место / персона / организация / событие / действие) и роль (обычный / старт / тупик / финал / проактивный с полем «триггер»). Необязательное поле «о ком» ссылается на сущность мира.
  - Улики — «что находят» и «как найти». Улика ведёт к узлу или к «тайне». Действует правило трёх улик.
  - Проходы — надёжные связи между узлами.
  - Вехи, награды сцен.
  - «Список выводов» за столом: что уже известно игрокам, найдено N из M.
- **Сеттинг (вики мира).** Вкладки: Обзор (описание, теги, кампании, изображения, проверка связей), География (дерево локаций, выходы между локациями), Население (личности, бестиарий, сообщества — одна сущность и для фракции, и для культуры, и для ордена), Приключения, Сокровищница (артефакты), Граф связей, Хроника мира (таймлайны, события, календарь: эры, месяцы, циклы), Ресурсы, Заметки.
- **Состояние кампании поверх содержимого.** Приключение хранит улики, тайны и вехи, а кампания — их состояние (найдено, раскрыто, пройдено) в отдельных таблицах. Это уже частичный «baseline + ветка кампании».
- **Игрокам.** Выдача сущностей игрокам «глазом» и статьи для игроков в кампании.
- **Связи.** Типизированные связи между любыми сущностями, @упоминания в тексте, граф связей с фильтрами по типам.
- **Пульт.** Экран Мастера за столом: панели, инициатива, список выводов, лента.
- **Библиотека.** Книги курсов с читалкой и заметками на полях.
- **Нет как отдельных сущностей:** часов / фронтов / угроз, нитей (threads), обещанных последствий, проектов даунтайма, «дельты сессии», видимости по отдельным персонажам.

Задуманная рабочая тетрадь — это универсальный конструктор. Шаблон пишется в Markdown и собирается из граф следующих типов:
- текст;
- строка;
- чек-лист;
- узкая таблица (фиксированные или свободные строки, до 3–4 столбцов);
- повторяемая карточка — для широких матриц: одна строка матрицы = одна карточка с подписанными полями;
- свободная страница;
- выбор из вариантов;
- картинка.

Число записывается строкой. В тексте есть @упоминания сущностей. Прогресс листа считается по чек-листу «Готовность».

## Что нужно выяснить

### 1. Инвентарь граф
Для каждого листа каждой тетради составь перечень граф. У каждой графы укажи:
- название;
- тип из списка выше, либо «не ложится», с объяснением почему;
- для таблиц и карточек — столбцы или поля;
- сколько раз графа заполняется: один раз, по разу на сущность (на персонажа, на фракцию…), по разу на сессию.

### 2. Жизнь графы после курса
Раздели графы на три вида:
- **учебные** — упражнение, после курса не нужно;
- **разовые решения** — заполнил на подготовке и перечитываешь (обещание, тон, рамка);
- **живые данные** — меняются по ходу кампании (отношения, часы, нити, что знают игроки).

Нужна доля каждого вида по каждой тетради. От этого зависит главное: тетрадь — это учебник или журнал кампании.

### 3. Соответствие приложению
Для каждой графы, кроме учебных, определи, куда она ложится:
- **(а) прямо на существующую сущность или поле** — какую именно;
- **(б) на сущность, у которой не хватает поля** — какого;
- **(в) на сущность, которой в приложении нет** — какой;
- **(г) только текст тетради** — сущность здесь не нужна.

Отдельно выпиши места, где тетрадь и приложение хранили бы одно и то же дважды. Это главный риск: двойной ввод делает подготовку сложнее.

### 4. Пересечения курсов
Найди понятия, которые встречаются в двух или трёх курсах под разными именами. Например: «точка атаки» и «рамка сцены», «фракция» и «сила», «часы» и «фронт». Предложи для каждого одно каноническое имя. Нужно, чтобы общие графы были одной графой конструктора, а не тремя похожими.

### 5. Проверки «Готовности»
Каждый пункт чек-листов «Готовность» отнеси к одному из видов:
- **проверяемый по данным** — например, «у каждой фракции есть цель», «у каждого вывода три улики»;
- **только самооценка Мастера**.

Для проверяемых напиши правило одной строкой.

### 6. Нагрузка на подготовку
Для каждого курса оцени три варианта:
- **A.** Тетрадь — отдельный текст с @упоминаниями.
- **B.** Графы тетради читают и пишут настоящие сущности кампании.
- **C.** Тетрадь — основной журнал кампании вместо разделов приложения.

Что каждый вариант добавляет Мастеру и что снимает, в шагах и повторных вводах, а не в общих словах. Помни: за столом у Мастера заняты голова и руки. Дополнительная настройка во время игры — это минус.

### 7. Выводы автора курса
По каждому из пяти пунктов раздела 15 в `Campaign_Course_04_NRI_Manager_Integration.md` скажи:
- что из этого уже закрыто существующими функциями приложения (см. список выше);
- что стоит добавить;
- что усложнит подготовку.

## Формат отчёта

Один файл Markdown: `[папка для отчёта]/course-analysis-report.md`.

1. **Коротко** — не больше 15 строк: ответ на главный вопрос и три-пять самых важных находок.
2. **Разделы 1–7** — таблицы там, где они естественны.
3. **Открытые вопросы к владельцу.** Туда всё, что нельзя решить по материалам.

Правила:
- Цитируй графы их точными названиями из тетрадей и давай ссылку «файл → лист».
- Если не уверен, так и пиши. Не додумывай содержимое, которого нет в файлах.
- Пиши по-русски.
