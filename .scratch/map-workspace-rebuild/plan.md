Второй шаг: готов [точный статический макет v1.1](mockups/index.html), 29 состояний на двух настольных разрешениях и 6 примеров узкой компоновки. По дополнительному запросу созданы [17 ассетов](mockups/asset-catalog.html); данж обновлён, подготовлен региональный пример. 2026-09-30 пользователь разрешил продолжить: v1.1 зафиксирована как опора для реализации. Реализованы MapDocumentV6 / soyman-map/3, sourceRef kind+uid, version/capability gate, независимые private токены, проверка источников/orphans и optimistic revision. [Отчёт шага модели](implementation/step-04/README.md). База редактора подключает полный V6 к инструментам/истории/сохранению и защищает уход; [отчёт](implementation/step-05/README.md). Старый маршрут сохраняет V5. V6 player flow закрыт до тикета 09; загрузка рабочую базу не преобразует.

## Решение
Новый map workspace в общей оболочке приложения: компактный левый rail, большой холст, постоянные поиск и мешок справа. Быстрое подземелье и художественная карта используют один документ. Из поиска/мешка размещаются связанные токены существ и локаций.
Новый экран строится рядом с текущим. Сохраняемые данные и пригодные части ядра переиспользуются после проверки.

## Этапы и результаты
| Этап | Работа | Результат и критерий перехода |
|---|---|---|
| 1. Контракты и границы | Сверить текущие фазы карт, модель V5, сохранение, проекцию и связи; определить typed token и стратегию версий | Зафиксированы версия/миграция, разрешённые источники, правила игрока, границы переиспользования |
| 2. Точный макет интерфейса | Перевести концепты в статические макеты с реальными шрифтами, ассетами и размерами; показать ключевые состояния на 1366×768 и 1920×1080 | Проверены размеры и читаемость, задано поведение панелей и окон, замечания разбора учтены; макет становится опорой для сборки UI |
| 3. Рабочее пространство | Контракт shell для стандартного режима / пульта / карт; библиотека карт, вход/выход, rail и правая панель | Обе панели заменяются, поиск и мешок сохранены, маршруты и возврат работают |
| 4. Базовое редактирование | Выбор, камера, сетка/snap, история, save; поверхности, комнаты, стены, двери, подписи, слои | Можно вручную сделать, сохранить и открыть маленький данж |
| 5. Связанные токены | Серверная валидация refs, разрешение имени/картинки, drag/drop из поиска/мешка, доступная альтернатива | Локация и существо размещаются, редактируются и сохраняются без изменения источника |
| 6. Быстрый генератор | Адаптер существующего алгоритма, параметры, пресеты, preview, применение одной командой | Генерация → редактирование → сохранение; seed повторяем |
| 7. Художественная карта | Измерение рендера, поверхности, кривые, scatter, набор согласованных ассетов | Ручная карта локации/региона с приемлемой отзывчивостью и качеством |
| 8. Показ и переносимость | Player projection, preview, PNG/thumbnail, показ в сессии, обмен без ошибочного relink | Все выходы согласованы, скрытые данные не утекли |
| 9. Переключение | Регрессия старых карт, backup/rollback, новый редактор по умолчанию, удаление старой UI-обвязки | Пройдены сценарии замены; текущие карты и отношения сохранены |

Этапы обозначают зависимости, не календарные сроки. После этапов 1–2 можно оценивать реализацию по реальным ограничениям и конкретному макету. Концепты не заменяют этап 2.

## Что входит в этап макета
- Изолированный статический HTML/CSS-макет и снимки ключевых состояний, без подключения к БД, генератору и сохранению продукта.
- Реальные шрифты и существующие декоративные ассеты; фиксируются размеры, отступы, контраст, зоны прокрутки и наложения окон.
- Экраны: библиотека/вход, пустая карта, готовый данж, активная кисть/дверь, выбранный токен, перенос из поиска, слои/ассеты, генератор, экспорт/вид игрока.
- Состояния: длинные имена, пустой/заполненный мешок, поиск без результатов/загрузка, сохранение/ошибка, отсутствие портрета, скрытый токен.
- Проверка основной композиции на 1366×768 и 1920×1080; отдельная компоновка поиска/мешка на узком экране.
- Действия и переходы описываются рядом с макетом. Работающее редактирование карты в этом этапе не требуется.
- Отдельно отмечается, какие детали художественной карты подтверждены существующими ассетами, а какие потребуют создания библиотеки. Красота цельной сгенерированной иллюстрации не считается доказательством качества будущего рендера.
- После разбора макета исправляются замечания и фиксируется версия, по которой собирается UI. Если при реализации потребовалось менять композицию, соответствующее состояние макета обновляется.

## Первая пригодная версия
Включает этапы 1–6 + минимальные части 8–9:
- Рабочая среда с компактными панелями.
- Ручные данжи: поверхности, комнаты, стены, двери, подписи и слои.
- Существа/локации из поиска и мешка как связанные токены.
- Генератор подземелий.
- Save, reload, undo/redo, PNG, preview игрока и показ в сессии.
- Совместимость существующих карт и offline-работа.

После неё — полный художественный набор этапа 7. Не включать в первую версию освещение, LOS, полноценную боёвку, сложные города, marketplace пакетов или прямой импорт нативных форматов Wonderdraft/Dungeondraft.

## Проверки
- Модель/сервер: token refs, round-trip, версия, отсутствие повреждения данных, player projection.
- Ввод: drop при pan/zoom, квадратной/hex-сетке и свободных координатах; undo/redo.
- Сценарии: модуль → поиск → токен → save → reload → игрок; генерация → правка → показ.
- Визуальная QA: 1366×768 и 1920×1080, длинные имена, пустые результаты/мешок, ошибки сохранения.
- Offline Electron: картинки, поиск и мешок доступны без внешних сервисов.
- Регрессия: репрезентативные старые карты, exploration, map_bindings, слои и экспорт.
- Производительность: заранее согласованные сцены малый данж / регион / много объектов. Измерить старт, pan/zoom, штрих, память и экспорт, определить допустимые лимиты.

## Следующие продуктовые решения
Defaults описаны в spec.md и уточнены ADR-0004; они не блокируют точный макет:
- Токены — being/location и монстры compendium_entry по уточнению пользователя 2026-09-30. Остальные виды добавляются отдельными задачами.
- Повторное размещение разрешено; мешок не расходуется.
- Свойства токена/слои — на холсте, правая панель остаётся поиском и мешком.
- Генерация новой карты по умолчанию; замена существующей — явно и undoable.
- При переносе между установками токен становится визуальной копией; автоматического связывания числовых IDs нет.
- Canvas2D сохраняется до измерения; решение о другом renderer основано на конкретной сцене.
- Стратегия версий выбрана: MapDocumentV6 / soyman-map/3. Capability gate и отдельный unsupported-путь реализуются до первого сохранения V6; старые карты переходят в новую версию при первой правке.
- sourceRef хранит kind+uid; numeric ID из поиска используется только для серверного разрешения источника.
- Новый токен по умолчанию private; публикация представления — явное действие мастера. Карточка источника и его права остаются отдельными.
- Новое сохранение защищается revision; конфликт и ошибки ухода должны быть показаны в макете.
