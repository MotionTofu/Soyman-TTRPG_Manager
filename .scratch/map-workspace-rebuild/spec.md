# Редактор карт как самостоятельный модуль SoyMan
Дата: 2026-09-30
Status: needs-triage
Область работы: план, концепты, точный макет и поэтапная реализация нового модуля по разрешению пользователя 2026-09-30.

Выполнены аудит/контракт, макет v1.1, рабочая оболочка, модель токенов, база нового редактора и размещение из поиска/мешка. [ADR-0004](../../docs/adr/0004-map-workspace-v6-tokens.md) реализован в части V6 kernel, soyman-map/3 master backup/import, стабильных UID, version gate и revision конфликтов. [Отчёт модели](implementation/step-04/README.md), [база редактирования](implementation/step-05/README.md), [токены](implementation/step-06/README.md). Новый V6 экран открывается обычным GM-кликом по карте и при создании; полный документ проходит через историю и conditional save/flush. Старый маршрут временно обозначен отдельной ссылкой для генератора и показа прежних карт до переключения 10. Публичная проекция — тикет 09.

## 1. Зафиксированные требования
- «Редактор карт» открывает самостоятельную рабочую среду внутри существующего приложения.
- Вход в модуль заменяет обычные левую и правую панели; возврат восстанавливает стандартную оболочку.
- Слева — компактные инструменты редактора.
- Справа обязательно остаются поиск и мешок, одновременно доступные в основном desktop-состоянии.
- Из поиска и мешка можно разместить на карте сущности: в первой версии локации и существа.
- Сущность появляется соответствующим токеном, сохраняющим связь с исходной записью.
- Быстрые генерируемые подземелья и ручное художественное создание используют один редактор и формат карты.
- Визуальный язык приближен к SoyMan_1shot: Fantasy Punk, бумага, ink, acid yellow, небольшие magenta-акценты.
- Холст получает основное место; настройки показываются по текущей задаче.
- Это модуль общего React-клиента, с действующими ролями, локальной БД и полной offline-работой в Electron.

## 2. Исходное состояние и полезные части
Проверено по текущим файлам рабочей копии, включая незакоммиченные изменения:
- `client/src/layout/AppShell.tsx`: есть переключение левой панели для пульта сессии. Подход пригоден как пример, но для карт нужен явный контракт рабочего пространства.
- `client/src/layout/SearchPanel.tsx` и `client/src/components/BagWidget.tsx`: оба источника используют общий `SEARCH_DRAG_MIME`, effectAllowed = link.
- `client/src/bag.ts`: мешок — существующее персональное промежуточное хранилище в localStorage; не новая коллекция объектов карты.
- `shared/src/maps/core/types.ts`: каноническая модель V5, слои, свободные координаты, gameplay entities. Типизированного связанного токена в текущем GameplayEntity нет.
- `client/src/maps/core/`: фасад общего ядра, миграция, валидация, изменения документа, серверная проекция для игроков.
- `client/src/maps/dungeon.ts`: сохранён детерминированный генератор. Сейчас выдаёт MapCells; MapEditorPage уже мигрирует его в V5 и валидирует. Этот адаптер выделяется из страницы и дополняется V6 upgrade.
- `client/src/maps/editor/`: камера, история, ввод, инструменты и viewport выделены; пригодность проверяется отдельно.
- `server/src/routes/maps.ts`: map_bindings связывает карту целиком с сущностью. Это не размещение токена в координатах.
- `client/src/pages/map-editor-layout.css`: нынешние боковые колонки до 220 + 290 px, несколько верхних рядов.
- `docs/adr/0003-map-core-v2.md` помечен draft, хотя текущий код уже использует V5. Нельзя принимать старый статус документа за реальное состояние реализации.

Существующие изменения пользователя не откатывать и не переписывать. Сначала сверить границы новой работы с текущими фазами в MainWorks/Maps/Recreate.

## 3. Рабочее пространство
### Вход и выход
- Пункт «Редактор карт» ведёт в библиотеку карт внутри map workspace.
- В библиотеке: существующие карты, «Пустая карта», «Быстрое подземелье», «Изображение как основа».
- При открытии карты библиотека в центре заменяется холстом, левый rail становится инструментальным.
- Никаких вложенных дополнительных левой/правой колонок внутри страницы редактора.
- Вверху всегда доступно «В приложение»; рядом «Карты» для перехода в библиотеку модуля.
- Поиск, мешок, пользователь и работающий звук не теряют состояние при смене workspace.
- Назад/вперёд браузера, прямой URL и перезагрузка корректно восстанавливают режим оболочки.
- При выходе редактор использует действующий жизненный цикл сохранения: pending save / error видны, незаписанный документ не теряется.

### Компоновка
| Область | Предложение |
|---|---|
| Верхняя полоса | 48–56 px: выход, имя карты, статус сохранения, undo/redo, экспорт, показ игрокам |
| Левая панель | Rail 56–64 px, один столбец инструментов, подсказки и hotkeys |
| Холст | Остальное пространство между rail и правой панелью |
| Контекстная строка | 36–40 px, параметры активного инструмента, без дополнительного заголовка страницы |
| Правая панель | 264–280 px, поиск сверху и мешок снизу |
| Свойства | Компактный popover в границах холста, по выделению/команде |
| Слои | Выдвижная панель поверх холста от левого rail, по запросу |
| Библиотека ассетов | Временный drawer над нижней частью холста, фильтры и поиск |
| Генератор / экспорт | Отдельные диалоги, закрываются после действия |

- При ширине 1366 px rail 64 + правая панель 272 оставляют примерно 75% ширины под холст; при 1920 px — около 82%.
- Это цель по ширине, не обещание такой же доли общей площади с учётом верхней полосы.
- Нет огромного H1, четырёх командных строк, постоянного инспектора или внешней навигационной колонки.
- Поиск и мешок имеют независимую прокрутку; пустой мешок занимает компактную нижнюю секцию.
- Tab временно скрывает боковые панели; кнопка восстановления остаётся доступна.
- На узком экране rail сохраняется, поиск/мешок открываются общей боковой шторкой с двумя секциями. Добавление без drag обязательно.

## 5. Связанные токены сущностей
### Термины
- Сущность: запись локации (`location`), существа населения (`being`) либо монстра бестиария (`compendium_entry`, только kind=monster) из общего домена. Поддержка бестиария уточнена пользователем 2026-09-30.
- Токен: отдельный размещённый экземпляр на конкретной карте.
- Asset: картинка или иной визуальный ресурс токена.
- Привязка карты: существующая связь map_bindings для карты целиком.
Токен, asset и привязка карты не заменяют друг друга.

### Сценарий размещения
1. Мастер находит сущность или берёт её из мешка.
2. Перетаскивает строку на холст. Видит призрачный токен и место установки.
3. При включённом snap токен становится в центр подходящей клетки; без snap — точно в world-координаты отпускания.
4. После отпускания создаётся один токен, выделяется и появляется в истории одним действием.
5. Подпись и изображение берутся из разрешённого источника сущности. При отсутствии картинки есть корректный fallback.
6. Повторный drop той же сущности создаёт другой токен с собственным ID.
7. Альтернатива: кнопка «Разместить» в строке включает установку следующим кликом на холсте; Escape отменяет.

### Внешний вид и действия
- Существо: круглый портрет, нейтральная рамка по умолчанию; без картинки — силуэт/инициалы.
- Локация: ромб/пин с изображением или подходящей пиктограммой; подпись с коротким именем при его наличии.
- Форма кодирует вид сущности; цвет используется для выделения и опционального обозначения группы.
- Небольшой значок связи отличает токен сущности от декоративного объекта.
- Клик выделяет; двойной клик или «Открыть сущность» показывает существующее preview без выхода из редактора.
- Можно двигать, менять размер, подпись, изображение, показывать/скрывать игрокам, дублировать и удалять.
- Удаление токена не удаляет сущность. Размещение из мешка не расходует его содержимое.
- Автоматическая боёвка, инициатива и синхронизация HP не входят в первую версию.

### Контракт по данным — результат фазы 1
В MapDocumentV6 расширить типизированный gameplay union сущностью GameplayToken с:
- собственным стабильным ID;
- position, size в world units, rotation;
- типизированным `sourceRef: { kind: "being" | "location" | "compendium_entry"; uid: string } | null`; numeric ID из drag разрешается сервером, null означает переносимую отсоединённую копию;
- appearance: рамка/форма и логическая ссылка на изображение, не постоянный внешний URL;
- labelMode: имя сущности или локальная переопределённая подпись;
- playerVisibility: private/public, по умолчанию private; публикация токена не открывает карточку сущности;
- минимальным публичным fallback для отсутствующего источника, только если он безопасен.

Нельзя просто положить SearchResult в `properties` или превратить декоративный MapObject в неявно связанную сущность.
Это расширяет перечень GameplayEntity из ADR-0003: изменение фиксируется отдельным ADR, с проверкой актуальной реализации общего ядра.
Выбраны MapDocumentV6 и soyman-map/3. До первой записи реализуются отдельный unsupported-version путь и server capability gate: будущая версия не считается повреждённой legacy-картой и не разрешает fallback overwrite. Загрузка старых карт мигрирует в памяти; запись новой версии только после правки с проверкой revision. Подробности и схема rollout — ADR-0004.
Сервер проверяет reference и права, а UI drag payload не считается источником истины.
Текущее имя/портрет разрешаются через общий доменный слой; локальные overrides хранятся у токена. Доступный offline-кэш изображений и обновление при смене галереи — часть реализации.

### Граничные случаи
- Неизвестный MIME, повреждённый payload, неверный ID и неподдерживаемый вид не изменяют документ.
- Существующие неподдерживаемые предметы мешка сохраняются; действие размещения для них недоступно с коротким пояснением.
- Несколько одноимённых сущностей различаются контекстом сеттинга/кампании в поиске.
- Отмена/ошибка разрешения сущности не оставляет пустого токена.
- Координаты учитывают offset холста, pan/zoom и CSS-размер; DPR используется рендером, не повторно в вычислении drop.
- Удалённая/архивированная сущность не ломает карту: master-вид показывает доступный fallback и состояние связи.
- Player projection фильтрует скрытые токены, ссылки и приватные подписи на сервере, в том числе у удалённых источников.
- JSON-экспорт в другой установке не должен связывать чужие числовые IDs с местными сущностями. Default: переносимые визуальные копии с безопасным fallback; relink — отдельное явное действие.
- Изменение токена не меняет сущность и не запускает новые отношения map_bindings.

## 6. Быстрые подземелья
- Один короткий диалог: размер, комнаты, коридоры/петли, ловушки, секреты, seed.
- Пресеты: «Маленькое», «Среднее», «Запутанное».
- «Новый вариант» меняет seed; те же параметры и seed воспроизводят ту же геометрию.
- Превью не меняет открытую карту до команды применения.
- Создание новой карты — действие по умолчанию; замена текущей явно обозначена.
- Применение к текущей карте — одна undo-команда, с предупреждением при замене содержимого.
- Выход генератора проходит адаптер и обычную валидацию документа; после применения доступны те же инструменты.
- Стиль оформления задаётся отдельно от генерации геометрии.
- Минимум два визуальных пресета: чистый чертёж и бумага/чернила.
- Перегенерация не стирает вручную размещённых сущностей скрытым побочным действием.

## 7. Художественное развитие
Следующая очередь после рабочего данжа:
- Масочные поверхности и мягкие границы земли/воды.
- Редактируемые кривые дорог, рек, берегов.
- Кисти лесов/гор и параметрическое рассеивание объектов.
- Объекты с вращением, масштабом, зеркалированием.
- Согласованные наборы текстур, объектов и стилей подписей.
- Региональные карты и позднее континенты.

Зафиксировать бюджет размера карт, числа объектов и памяти по реальному рендеру. Canvas2D пригоден как начальная проверяемая база; выбор нового renderer принимается после короткого измерения на целевой сцене. React управляет оболочкой/настройками, а не тысячами отдельных DOM-объектов карты.

## 8. Стиль
- OneShot appearance подключается локальным scope map workspace, не меняет глобально весь SoyMan.
- База: тёплая бумага, ink #171717, acid yellow #F3FF3A; magenta #FF3E91 — редкий вторичный акцент.
- Прямые края, срезанные углы, тонкие линии, умеренные hard shadows.
- Шум/halftone — на краях и разделителях; точный холст и поля ввода спокойные.
- Активный инструмент читается и по форме/рамке, не только по цвету.
- Совместимые ассеты берутся из SoyMan_1shot/assets/fantasy-punk и client/public/ui/fantasy-punk.
- Растровый концепт не используется как готовая UI-панель: будущие элементы реализуются обычными контролами.
- Стиль UI не навязывает карту: чертёж, пергамент, природные цветные карты допустимы.

## 9. Приёмка замены
- Мастер входит в модуль и возвращается без потери мешка, звука и рабочего состояния.
- Поиск и мешок видны вместе на desktop; свойства и слои их не заменяют.
- При 1366×768 доступен весь набор основных действий без горизонтального скролла.
- Токены существа и локации устанавливаются drag и альтернативой без drag, после pan/zoom.
- Несколько токенов одной сущности сохраняются, имеют независимые ID и корректный undo/redo.
- Исходная сущность после удаления токена остаётся.
- Карта/токены восстанавливаются после перезагрузки и работают offline.
- Игрок не получает скрытые токены и приватные данные; preview, PNG и показ игрокам согласованы.
- Существующие карты проходят round-trip и визуальную проверку без потери слоёв, объектов, связей и exploration.
- Генератор повторяем; результат редактируем; применение undoable.
- Новый редактор допускает корректное сохранение ошибок/несовместимости и не затирает неподдерживаемый документ.
- Старый UI удаляется только после прохождения сценариев замены, резервной копии и проверенного возврата.
