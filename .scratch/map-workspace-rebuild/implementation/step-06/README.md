# Шаг 05: связанные токены из поиска и мешка

Дата: 2026-09-30. [Тикет](../../issues/05-entity-placement.md) · [План](../../plan.md) · [ADR-0004](../../../../docs/adr/0004-map-workspace-v6-tokens.md).

В новом редакторе `/maps/:id/workspace` можно перетаскивать существ и локации из общего поиска и мешка. Кнопка «Разместить на карте» в поиске и «На карту» в мешке запускает размещение без перетаскивания: точка на холсте, стрелки и Enter либо «Поставить здесь». На узком экране панель поиска закрывается, освобождая холст.

Дополнение 2026-09-30: [исправлены обычный вход и перенос бестиария](drag-fix/README.md). Основной редактор теперь открывается обычным кликом и при создании карты; разрешены being/location и монстры compendium_entry, включая прежние записи мешка без subtype. Ниже сохранён исходный отчёт шага 05; актуальные результаты дополнительной проверки — в дополнении.

Каждое размещение — отдельный экземпляр с новым UUID. Повторный перенос разрешён; мешок сохраняет свою запись, исходная сущность не удаляется и не редактируется. Токен можно двигать, менять размер/поворот/форму и подпись, выбирать портрет или силуэт, открывать карточку поверх карты, отсоединять от источника и удалять. Undo/redo и обычное сохранение работают с полным V6.

## Поведение и защита данных

- Общий payload проверяется: только being/location и положительный безопасный integer ID. Имя, UID и URL из payload игнорируются. Связь разрешается сервером; канонический документ хранит kind+UID и логическую ссылку на портрет, без URL, локального ID и динамического имени.
- Пока источник загружается, существует только ghost. Drop использует world-координаты точки переноса, кнопка позволяет выбрать точку/подтвердить. DPR относится только к буферу Canvas. Привязка независима от видимости сетки и поддерживает квадратные/шестигранные клетки.
- Выбранный gameplay-слой сохраняется как цель, включая явный отказ при его блокировке/скрытии. Если выбран другой вид слоя, берётся верхний доступный gameplay. После resolver цель проверяется повторно. Неудача не создаёт токен или запись истории.
- Escape, новое размещение, смена карты/прав и размонтирование отменяют поздние ответы. Отмена не портит документ. Простое выделение токена не создаёт правку.
- GM-представления разрешают актуальные короткие имена и основные портреты; для существа без собственного портрета допускается портрет базового монстра, как в его карточке. Портрет должен быть локальным изображением внутри хранилища. Загрузка идёт с авторизацией. Ошибка изображения оставляет имя и силуэт; недоступный источник — явную заглушку.
- Сведения обновляются при открытии карты, возврате фокуса и адресных изменениях источников. Удалённый/архивный источник не каскадно удаляет сохранённые токены и не блокирует их перемещение, удаление или detach.
- Публичный V6 остаётся закрыт до 09. Новый токен private; настройка видимости готовит будущее представление, доступ к исходной карточке не публикует. Никакой player-проекции из raw token не строится на клиенте.

## Проверка

Итог: **518 тестов клиента / 51 файл**, **64 серверных теста / 4 файла**. Повторены **10 браузерных групп сценариев токенов** и **10 групп базовой регрессии редактора**, без runtime/React console errors. [Базовая регрессия](basics-regression/browser-qa.json) включает комнату/дверь/поверхности/подпись/объект, слои, camera, Escape, автосохранение, ошибку ухода, same-document Back и private copy опубликованной старой карты.

[Browser QA](browser-qa.json): native drag из обоих источников; доступное размещение из поиска/мешка; повторные экземпляры; мешок остаётся целым; один undo/redo; размер/поворот/подпись и перемещение; портреты; карточки существа и локации на холсте; save/reload; malformed/unsupported payload; resolver failure; отмена и уход во время resolver; offset/pan/zoom и DPR 2; отсутствие snap; актуальное имя; orphan fallback и detach; размеры 1366×768, 1920×1080 и 820×900; hex snap; явный locked target. Runtime/React console errors отсутствуют. [Сценарий](check-tokens.mjs).

Автотесты проверяют чистый адаптер, канонический round-trip, refs/order, неподвижное выделение, слой, независимые ID, transient представления, неудачную загрузку картинки/источника и гонки отмены/смены карты/нового размещения. Серверные тесты проверяют текущие имена/портреты, GM-only доступ, capability, архив, invalid/oversized batch, неизменность карты и источника, сохранение orphan/ref validation и прежние карты. Они используют только временную БД/хранилище; браузер перехватывает все API и использует явно тестовые сущности. Сервер на рабочей БД не запускался.

Проверка типов клиента и Vite bundle проходят. Scoped lint новых файлов без замечаний. В общем серверном TypeScript-прогоне обнаружены три ошибки `template is unknown` в параллельно создаваемом `server/src/db/workbooks.ts`; к этому шагу карт они не относятся и не изменялись. В сборке остаётся прежнее предупреждение о размере отдельных JS chunks. Полный `npm build` со всеми глобальными style guards не заявляется.
