# Иерархия карт (отложено, не фундамент)

Идея владельца: объект на карте → клик → открывается новая (дочерняя) карта.

## Замысел
- Маркер-портал: клетка/объект хранит `target_map_id`.
- Клик в редакторе — выбор/правка маркера; клик в режиме просмотра — переход.
- Цепочка: Планета → Континент → Страна → Регион → Населённый пункт → Местность.

## Почему не в фундаменте
Требует дерева связей, навигации «вверх/вниз», хлебных крошек между картами и решения о наследовании привязок (дочерняя карта наследует видимость/сеттинг родителя или нет). Фундамент сначала: одна плоская карта рисуется, хранится, отменяется, экспортируется.

## Минимальный задел под это (без кода иерархии)
- В `maps` сразу заложить `parent_map_id NULL` + `parent_label` (откуда провалились).
- В клетке заложить поле `portal_to_map_id NULL` (пока нигде не используется, в UI не показывается).
- Когда дойдём — включаем UI маркеров и крошки без миграции.

## Открытые вопросы (на будущий разбор)
1. Один портал → одна карта или список («три пещеры в этой горе»)?
2. Наследует ли дочерняя карта привязки и видимость для игроков?
3. Что видит игрок при провале в скрытую карту?
4. Удаление родителя — каскад, осиротение или запрет?
