# Пакет A — Слой объектов (спека)

Источник: грилинг 2026-09-03 (прототип `E:\Claude\DeepS\dungeon.html` → раздел Карты).
Порядок пакетов: A → B → D → C. Всё в `MainWorks/Maps/`, `design_revision.md` не трогаем.
Статус: спека утверждена, код не начат.

## 1. Состав слоя

Три списка + комнаты. Всё — в blob клеток, формат **v3**:

```text
{v: 3, cells: {...}, roads: [...], labels: [...],
 rooms: [{x, y, w, h, type, name}],
 doors: [{x, y, edge, kind, secret, pair}],
 traps: [{x, y, kind}],
 start: {x, y} | null, finish: {x, y} | null}
```

- `rooms`: `type` ∈ `empty/barracks/temple/treasury/prison/lab`, `name` ≤ 64 (пустое = без имени).
- `doors`: `edge` ∈ `n/s/e/w` (квадраты; гексы — следующим шагом, см. §7),
  `kind` ∈ `arch/door/locked/trapped/secret/portc`, `secret: bool`,
  `pair: string | null` (общий id парных дверей широкого прохода).
- `traps`: `kind` ∈ `pit/arrow/gas/glyph`.
- v1/v2 читаются как раньше (списков нет = пусто). Клиент битые записи роняет
  поштучно, сервер валидирует строго.

## 2. Капы валидации (сервер)

Комнат ≤ 100, дверей ≤ 400, ловушек ≤ 300 (подписи уже ≤ 200).
Тексты ошибок в стиле существующих (`rooms too many (max 100)` и т.п.),
клиентский `translateMapError()` дополняется тремя кейсами.

## 3. Рендер (поле)

Порядок поверх террейна/сетки: комнаты-тинт → двери → ловушки → старт/финиш → подписи.
- Комната: тинт типа (пастель, `opacity 0.18`, как в прототипе) + номер; изолированность
  пока НЕ считаем (нет графа связности до пакета C).
- Дверь: чёрная подложка-линия поперёк ребра + цветной прямоугольник вида + глиф.
  Цвета видов из прототипа приглушить под палитру (§7): секрет — синий, заперта — красный,
  ловушка — оранжевый, арка — зелёный, решётка — фиолет, дверь — охра.
  Глифы: `○ ◫ ⚿ ⚠ S ▦` — тип формой, не только цветом.
- Ловушка: плашка + символ (`◉ ➤ ☠ ✦`).
- Старт: зелёный круг + «СТАРТ»; финиш: шахматка 2×2 + «ФИНИШ» (как в прототипе).
- Всё — экранными размерами с порогом: объекты рисуются при `scale >= 10`,
  глифы/текст при `scale >= 14` (иначе каша). Culling по видимому диапазону,
  как террейн (P1-5).

## 4. Взаимодействия (мастер)

- **Клик-панель** (не ПКМ — ПКМ остаётся ластиком, P1-10; тач-friendly):
  клик по двери → панель (вид ×6, флаг секретности, удалить);
  по ловушке → панель (вид ×4, удалить); по комнате → панель (тип ×6, имя, удалить).
  Панель — та же модалка, что у подписей.
- **Drag** (рука отдельным инструментом НЕ вводится): схватил дверь/ловушку/
  старт/финиш/комнату — потянул. Дверь кладётся только на ребро прохода
  (комната↔коридор/комната), иначе тост «Дверь — только в проход».
  Комната двигает краску (стены/пол) + пересоздаёт двери проходов, один undo-шаг;
  ручные двери рядом могут пострадать — в confirm так и пишем.
- Коридоры — краска (кисти уже есть), не сущности.
- Хоткеи: `T` занята подписью; объекты — клик-панель без хоткеев на первое время.
  `Delete` удаляет выбранный объект (пару дверей — целиком).

## 5. Парность дверей

Проход шириной 2 → две двери с общим `pair`. Двигаются/меняют вид вместе;
перетаскивание пары на одиночный проём — схлопывание в одну (вторая удаляется);
одиночной на двойной — раздвоение. Логика — портом из прототипа
(`stopDragDoor`: группы сегментов прохода).

## 6. Видимость игрокам

- `secret: true` или `kind === 'secret'` → скрыта полностью (как стена).
- `trapped` → видна обычной дверью (вид подменяется, флаг не светится).
- Ловушки скрыты все. Старт/финиш видны. Комнаты/тинты видны, имена — видны.
- Тумблер «Глазами игрока» в редакторе (превью без второго окна) — входит в A.
- Сервер: `GET /:id` игрокам — чистить секретное из blob на отдаче
  (не отдавать то, что скрыто, а не прятать на клиенте).

## 7. Не в A (следующие шаги слоя)

- Гексы: рёбра `n/s/e/w` → 6 направлений, соседи по odd-q. Отдельный заход.
- Связность/починка изолированных (пакет C, нужен граф).
- Типы водоёмов, Foundry-экспорт (пакет D).

## 8. История/сохранение/экспорт

- Любая правка слоя — undo-шаг (мазок/перетаскивание целиком/панель целиком),
  глубина 50 общая. Автосейв шлёт весь blob (списки внутри) — капы §2 держат размер.
- PNG: объекты вшиваются (вид игрока — без секретного, вид мастера — всё);
  легенда PNG дополняется видами дверей.
- Миниатюры списка — тем же рендером (объекты видны мельком, пороги масштаба
  их сами погасят).

## 9. Тесты

- Валидация: v3 ok, плохие edge/kind/координаты/тексты, превышение капов,
  v1/v2 обратно совместимы.
- API: игрокам секретное не отдаётся (unit на чистку blob), POST/DELETE гейты.
- Клиент: чистка парности (схлоп/раздво), порог глифов — ручной прогон владельцем.

## 10. Критерии приёмки

1. Дверь ставится кликом в проход, меняет вид панелью, тащится на соседний проход.
2. Широкий проём даёт пару; пара двигается/схлопывается по §5.
3. Секретная дверь и ловушки не видны игрокам ни в API, ни в PNG игрока; тумблер превью это показывает.
4. Таскание комнаты двигает краску + двери одним undo-шагом.
5. `tsc`, шкала кегля, серверные тесты зелёные; ручной прогон в панке и нуаре.
