## I. Графический дизайнер-перфекционист

### D1. Легенда PNG не использует штриховки мотивов ( mismatch легенды и карты) — [Дизайн, Мастер]
- **Файл:** `MapEditorPage.tsx:1326–1379`
- PNG-легенда рисует **сплошные** цветные свотчи 14×14 + название. Но на самой карте террейны имеют **штриховки** (волна, сосна, шеврон и т.д. — `render.ts:82–193`). Мастер, смотря на распечатку, видит на карте «ёлочки», а в легенде — зелёный квадрат. Для heavily-лесной карты это не критично (лес узнаётся), но для **подземелий** (стены = кирпичный мотив) и **водных карт** (волны на мелкой/глубокой воде) мотив — основной способ различить террейны одного тона.
- **Приоритет:** средний. Не ломает, но снижает ценность печатной карты.
- **План:** в легенду PNG добавить мотив-символ рядом со свотчем (одна-две lines/shapes из `drawTerrainMotif`, ужатые в 14×14). Альтернатива — текстовый глиф (≈ «≈» для воды, «♠» для леса) без canvas-рисования.

### D2. Координаты A1 в PNG без трекинга выглядят сжато — [Дизайн]
- **Файл:** `render.ts:803–816`
- На экране координаты идут с `letterSpacing: 0.08em` (P1-3, зафиксировано). В PNG-экспорте тот же `renderMap` вызывается с теми же параметрами — трекинг **должен** применяться. Но `ctx.letterSpacing` — API canvas, не CSS; поддержка в Chromium/FF есть, в Safari — нет. В Safari-пейджере (если распечатать через «Файл → Печать») координаты A1 и B3 сольются.
- **Приоритет:** низкий. Safari — нишевый сценарий для TTRPG.
- **План:** проверить Safari; если сломано — fallback через `ctx.fillText` с ручным spacing (пробелы между символами).

### D3. Текст «1 клетка = …» в PNG-легенде нестрого моноширинный — [Дизайн]
- **Файл:** `MapEditorPage.tsx:1381–1382`
- Шрифт задан как `"12px monospace"`, что应当 использовать `--font-mono` (JetBrains Mono по §1.5). Но в canvas-контексте `var(--font-mono)` не работает — это CSS-переменная, а не canvas-шрифт. Фолбэк `monospace` на разных ОС = разная ширина (Courier New vs Liberation Mono). Для «1 клетка = 2 км» разница незаметна, но если cell_lore = «0,5 фута» — моноширинность нужна для выравнивания.
- **Приоритет:** низкий.
- **План:** canvas не поддерживает CSS-переменные; принять `monospace` как есть (достаточно для строк ≤20 символов).

### D4. Режим «Глазами игрока» + легенда = несоответствие — [Дизайн, Мастер]
- **Файл:** `MapEditorPage.tsx:1317–1335`
- Легенда PNG строится из `MAP_TERRAIN_ORDER` (все 13 террейнов) + **виды дверей с карты** с учётом `pv` (player view). Но террейны **всегда** все — даже если на карте нет ни одной лавы/кислоты/яда, легенда покажет все 13 свотчей. Игрок видит легенду с «Лава», «Кислота», «Яд» на карте, где их нет — это спойлер (мастер может использовать их позже).
- **Приоритет:** средний. Спойлер через легенду — реальный риск.
- **План:** в режиме «Вид игрока» легенду PNG фильтровать: показывать только террейны, реально присутствующие на карте (遍历 `cells.terrain`), плюс дорога; двери — как сейчас. Для мастера — все террейны как было.

### D5. Печатная карта не учитывает реальный размер A4/A3 — [Мастер]
- **Файл:** `MapEditorPage.tsx:1276–1383`
- PNG экспортируется в пикселях (density 16–48 px/кл). Мастер печатает через «Файл → Печать» браузера или открывает в Paint/Photoshop. Нет информации о **реальном размере** на бумаге. Регион 60×44 при 32 px/кл = 1920×1408 px; при 96 dpi это ~51×37 cm — запросто не влезает в A4 (21×29.7 cm). Мастер печатает, получает обрезанную карту или два мелких листа без понимания масштаба.
- **Приоритет:** средний. Печать — один из ключевых сценариев (PRODUCT.md: «in-person play is the default»).
- **План:** в панель PNG добавить readout реального размера при выбранной плотности («~51×37 cm при 96 dpi»); позже — раскладка на листы (split export).

### D6. Мини-карта (minimap) не показывает террейн-LEGRO — [Дизайн]
- **Файл:** `MapEditorPage.tsx:3051–3093`
- Миникарта — data URL от `renderThumbnail()`, та же карта в миниатюре. Рамка вьюпорта — `1px solid var(--ink)`. В миникарте **нет координат и легенды** — это правильно (маленький размер). Но нет и **масштаба** — мастер не видит, сколько клеток влезает в текущий вид. На миникарте 132 px шириной карта 60×44 — одна клетка ~2 px, читаемость нулевая. Рамка вьюпорта полезна, но без понимания «сколько я вижу» —.relative.
- **Приоритет:** низкий.
- **План:** в титул миникарты добавить «Видимо: ~12×9 клеток» (рассчитать из `wrect` и `cam.scale`).

## II. Программист: код, уязвимости, оптимизация

### C1. `exportPng()` — синхронный рендер большого canvas может заблокировать UI — [Код]
- **Файл:** `MapEditorPage.tsx:1276–1383`
- При плотности 48 px/кл и поле 100×100: `mapW = 100×48 + pad×2 ≈ 4848 px`, `mapH ≈ 4848 px` → **23.5 млн пикселей**. `renderMap` + `fillText` для легенды + `drawImage` — всё синхронно в одном тике. На среднем ноутбуке это 1–3 секунды заморозки UI. При 100×100 и 48 density — до 5 сек. Пользователь видит «заг冻ел», жмёт повторно — получает два PNG.
- **Приоритет:** средний. Не ломает данные, но раздражает и может вызвать двойной экспорт.
- **План:** обернуть в `requestIdleCallback`/`setTimeout` + показать «Генерируется…» Disabled-кнопку; или `OffscreenCanvas` + web worker (сложнее, но чище). Минимальный фикс — `setTimeout(() => { ... }, 0)` + disable кнопки на 2 сек.

### C2. `floodFill()` без ограничения глубины рекурсии (stack-based, но...) — [Код]
- **Файл:** `MapEditorPage.tsx:112–142`
- Реализация через `stack.push/pop` — правильная (не рекурсивная). Но `seen` и `stack` растут пропорционально заполненной области. На поле 100×100 заливка всей карты = 10 000 клеток в `seen` Set + до 40 000 в `stack` (4 соседа на клетку). Это ~500K–1M JS-объектов. Не критично, но если пользователь зальёт «Кислотой» всю 100×100 карту — будет заметная пауза (200–500 мс).
- **Приоритет:** низкий. Крайний случай, откат заливки — один undo.
- **План:** оставить как есть (альтернатива — BFS через очередь, та же сложность); при необходимости — добавить лимит `seen.size > 20000` → «Слишком большая область».

### C3. `cloneCells()` на каждый mousedown/move/up — [Код, перф]
- **Файл:** `MapEditorPage.tsx:56–67`, вызовы в `paintAt` (1396), `singleAction` (1428–1429), `beginStroke` (1406), `moveObjTo` (967)
- Каждый `pointermove` при рисовании = `cloneCells(cellsRef.current)` = копирование `Map` + `Set` + 4 массивов + 2 nullable объектов. На карте 60×44 с 500 расписанными клетками — это ~10 000 entries в `terrain` Map, каждый move клонирует его. При быстром движении мыши (~60 moves/сек) = 600K клонирований Map в секунду. В реальности GC справляется (каждое клонирование — новый Map, старый уходит в Gen0), но на слабых устройствах (Chromebook, планшет) будет micro-stutter.
- **Приоритет:** средний. Заметно на слабых устройствах.
- **План:** в `paintStroke` не клонировать, а **мутить** черновик и хранить `before`-снапшот отдельно (undo-шаг). Текущая архитектура: `clone → mutate → setCells → check changed`. Альтернатива: `mutate draft directly → if changed, save before as undo`. Убирает ~50% клонирований.

### C4. `renderMap()` не кэширует `byTerrain` между кадрами — [Код, перф]
- **Файл:** `render.ts:528–543`
- Каждый кадр заново группирует `cells.terrain` по типу в `Map<string, array>`. Для 500 клеток это 500 итераций + 500 `split(',').map(Number)` + 500 проверок `inView`. На 60 fps это 30 000 итераций/сек. Не тяжело, но лишнее — `cells` не меняется между кадрами (меняется `cam`, `hover`).
- **Приоритет:** низкий. Оптимизация premature без реального бенефита.
- **План:** оставить; если будет micro-stutter — мемоизировать `byTerrain` через `cells`-версию (сравнение по ссылке).

### C5. `putHistory()` не проверяет дублирование снапшотов — [Код]
- **Файл:** `MapEditorPage.tsx:264–270`
- `pushHistory(before)` пушит **ссылку** на `MapCells`. `cloneCells` создаёт новый объект, но если `before` уже является клоном (все вызовы передают `cloneCells(cellsRef.current)`), это корректно. Но если два быстрых действия (fill + undo нажатие) пушат один и тот же `before` (потому что `cloneCells` был вызван до изменений) — undo будет прыгать через состояние. Не баг в текущем коде (undo вызывается вручную, не автоматически), но хрупко.
- **Приоритет:** низкий.
- **План:** не трогать; архитектура «clone → mutate → push(clone)» корректна по конструкции.

### C6. `serializeCells()` вызывается дважды за автосейв — [Код]
- **Файл:** `MapEditorPage.tsx:337–338` (в `useEffect` для change detection) и `344` (в `sendSave`)
- `serializeCells(cells)` — полная сериализация blob. В `useEffect` она нужна для сравнения с `lastSavedRef.current`. В `sendSave` — для отправки. Это две полные сериализации за один автосейв-тик.
- **Приоритет:** низкий.
- **План:** вычислить `cellsStr` один раз и передавать в `sendSave`; текущий код уже делает `const cellsStr = serializeCells(cells)` в useEffect и передаёт в `sendSave({ cellsStr, ... })` — **дублирования нет**, я ошибся при первичном чтении. Код корректен.

### C7. `MapEditorPage.tsx` — 3124 строк, один файл — [Код, поддерживаемость]
- **Файл:** `MapEditorPage.tsx`
- Один компонент содержит: рендеринг, логику инструментов, генератор, дженератор, экспорт PNG, экспорт JSON, привязки, настройки, все модалки, drag-логику, touch-логику, undo/redo, autosave, камеру, хоткеи. Это ~3100 строк одного `export function`. Любой рефакторинг (вынос модалок, вынос touch-логики, вынос экспорт-панелей) требует понимания десятков рефов и замыканий.
- **Приоритет:** средний. Не баг, но technical debt.
- **План:** рефакторинг по частям: (1) вынести модалки в отдельные компоненты, (2) вынести touch-обработчики в hook, (3) вынести генератор/экспорт в отдельные панели-компоненты. Без спешки — делать при следующем багфиксе в этой области.

### C8. `generateCells()` создаёт巨大的 промежуточные массивы — [Код]
- **Файл:** `generate.ts:83–98`
- Два прохода по полю (100×100 = 10 000 клеток): первый — `mountainNoise[]` + `isLand[]` (два массива по 10K чисел), второй — основной. Затем `landNoises` — копия + сортировка. На 100×100 = 10K浮点数 × 3 массива = ~240 KB памяти. Не критично, но на 50×50 (самый частый размер) — 10× меньше.
- **Приоритет:**很低.
- **План:** не трогать.

### C9. `dungeon.ts` — `carveBetween` может выйти за границы после clamp — [Код]
- **Файл:** `dungeon.ts:189–208`
- После `carveH(sr, sc, ec, w)` и `carveV(ec, sr, er, w)` — оба вызова используют `ec` как начальную колонку для `carveV`. Если `ec` был обрезан clamp'ом (строка 200–201), то `carveV` начнёт с обрезанной колонки, что корректно. Но `sr`/`er` для `carveV` берутся из аргументов (не clamped), а `carveV` внутри проверяет `inB` — так что всё безопасно. Проверено.
- **Приоритет:**很低.
- **План:** не трогать.

### C10. SQL-инъекция через `bindingTargetName()` — [Безопасность]
- **Файл:** `maps.ts:216–226`
- `targetType` передаётся в SQL: `` `SELECT name FROM ${table} WHERE id = ?` ``. Но `table` вычисляется через `if/else` из `targetType`, который **строго** проверен через `MAP_BINDING_TARGETS` (`maps.ts:250`). SQL-инъекция невозможна — `targetType` не может быть чем-то кроме `"setting"|"campaign"|"location"`. Безопасно.
- **Приоритет:**很低.
- **План:** не трогать.

## III. Придирчивый пользователь (юзабилити)

### U1. Нет индикации «было изменено, ещё не сохранено» на уровне вкладки — [UX]
- **Файл:** `MapEditorPage.tsx:193–196`
- `saveState` показывает «Сохранено HH:MM» / «Сохранение…» / «Есть несохранённое…» / «Не сохранилось» **только в тулбаре редактора**. Если мастер открыл карту, сделал правку и перешёл на другую вкладку браузера (или в другое приложение), он **не видит** индикатора. При закрытии вкладки `beforeunload` предупреждает, но предупреждение браузера — «Выйти с сайта?» без контекста «у вас несохранённые изменения на карте XYZ».
- **Приоритет:** средний. Потеря данных — реальный риск при multi-tab.
- **План:** обновить `document.title`: `"● Карта XYZ — SoyMan"` при dirty, `"Карта XYZ — SoyMan"` при saved. Стандартный паттерн (Google Docs, Figma). Реализация: один `useEffect` от `saveState.kind + map.name`.

### U2. Нет undo/redo-пapeshки (история действий) — [UX, Мастер]
- **Файл:** `MapEditorPage.tsx:264–290`
- Undo/redo работают, но нет **визуального отображения** истории. Мастер не знает, сколько шагов назад он может откатиться, и что именно было сделано. При 50 шагах (`UNDO_DEPTH = 50`) это длинная цепочка, и «что я отменю?» — вслепую.
- **Приоритет:** средний. Не критично, но снижает доверие к undo.
- **План:** выдвижная панель справа (accordion или sidebar) со списком последних N действий (напр. «Кисть: лес ×12», «Заливка: вода', «Подпись: Вотердип», «Генерация: сид 12345»). Клик по шагу — jump-to. Позже.

### U3. Нет быстрого переключения между последними двумя картами — [UX]
- **Файл:** `MapEditorPage.tsx`
- Мастер часто porównивает две карты ( «какая карта кампании?»). Сейчас: Back → список → клик → загрузка. Нет keyboard shortcut для toggle между последними двумя.
- **Приоритет:**很低.
- **План:** запоминать `lastMapId` в localStorage, добавить hotkey `Ctrl+Tab` → переход.

### U4. Кнопка «Очистить» рядом с «Undo» — риск случайного нажатия — [UX]
- **Файл:** `MapEditorPage.tsx:2257–2259`
- «Очистить» — `useConfirm` есть, но кнопка расположена **рядом с Undo/Redo** (строки 2246–2256). Визуально: `[←] [→] [Очистить]`. Мастер жмёт «→» (redo), промахивается — «Очистить» → confirm. Если confirm открыт и мастер жмёт «Enter» по привычке (подтвердить.undo) — очистит карту.
- **Приоритет:** низкий. Confirm защищает, но UX-ловушка.
- **План:**移動 «Очистить» вправо, подальше от undo/redo; или добавить `cancelLabel: "Не очищать"` (уже есть) + пометить кнопку удаления как `danger` визуально (CSS class).

### U5. Minimap не обновляется при каждом мазке — [UX]
- **Файл:** `MapEditorPage.tsx:499–506`
- Миниатюра обновляется через `setTimeout(800)` после последнего изменения `cells`. При активном рисовании (60 moves/сек) миниатюра обновляется **раз в ~2.5 сек** (ingerprint: `Date.now() - cached.at < 2500 → return null`). Это правильно для производительности, но мастер, рисуя большой регион, не видит превью — «я вообще где нахожусь?».
- **Приоритет:** низкий.
- **План:** оставить (оптимизация важнее); альтернатива — отдельный «Обновить миникарту» кнопка.

### U6. Панель генератора не запоминает вкладку «Суша/Подземелье» — [UX]

### U10. Фильтр «Видят игроки» не объясняет, что это — [UX]
- **Файл:** `MapsListPage.tsx:274–285`
- Селект: `Все карты / Видят игроки / Скрыты`. Нет `title`-объяснения (а есть `aria-label`). Новый мастер не понимает: «Скрыты — от кого?»
- **Приоритет:** низкий.
- **План:** в `title` селекта: «Фильтр по видимости игрокам: игроки видят только карты с галочкой "Видят игроки"».

## IV. Мастер: подготовка к игре и печать

### M1. Нет «быстрого черновика» (открыть пустую карту и сразу рисовать) — [Мастер]
- **Файл:** `MapsListPage.tsx:192–225`
- Создание карты: модалка → ввести имя → выбрать сетку → выбрать масштаб → ввести размер → «Создать и открыть». Это **4 поля + 1 клик** для пустой карты. Мастер хочет: «+ Карта → рисую». имя можно дать потом (уникальный auto-name через `Карта №N`).
- **Приоритет:** средний. Барьер входа.
- **План:** дефолтное имя = `Карта ${maps.length + 1}` (или timestamp); один клик «+ Быстрый черновик» → дефолты (hex, continent, 40×30) → переход в редактор. Модалка — «Полная настройка» отдельной кнопкой.

### M2. Нет «пакетной заливки» для данжей (залить все полы одним типом) — [Мастер]
- **Файл:** `MapEditorPage.tsx`
- Данж-генератор ставит `wall` и `plain` (полы). Если мастер хочет залить **все** полы «Холмами» (подземный лес) — заливка (`G`) заливает **связную** область. Полы данжа связаны через коридоры, но если есть изолированные комнаты — каждую заливать отдельно.
- **Приоритет:**很低.
- **План:** режим заливки «все клетки типа X → заменить на Y» (модалка: «Заменить все равнины на холмы?»). Позже.

### M3. Легенда редактора (toggл) не показывает штриховки — [Мастер]
- **Файл:** `MapEditorPage.tsx:2358–2403`
- Легенда редактора — сплошные квадраты + текст. Как и PNG (D1), нет мотивов. Мастеру приходится **помнить**, что «зелёный с ёлочкой = лес, а зелёный с былинками = болото».
- **Приоритет:** средний. Прямое следствие D1.
- **План:** в CSS-легенду добавить текстовые глифы (≈ для воды, ♠ для леса) через `::after` или отдельный span.

### M4. Комната без названия показывает только номер — [Мастер]
- **Файл:** `render.ts:615–639`
- Комната без `name` = только номер (`String(idx + 1)`). При 10+ комнатах цифры 1–10+ — неинформативно. Мастер не помнит, «что в комнате 7».
- **Приоритет:** средний.
- **План:** дефолтное имя по типу: `Казарма 3` (тип + номер) или `Комната 3` для `empty`.

### M5. Нет способа добавить «テストового персонажа» на карту для боя — [Мастер]
- **Файл:** `MapEditorPage.tsx` (инструмент «Выбор»)
- Слой объектов: комнаты, двери, ловушки, старт/финиш. Нет ** маркеров NPC/монстров/персонажей**. Для тактического боя мастеру нужно: «Гоблин стоит здесь». Сейчас — только через `LocationMap` (отдельный компонент, не редактор карт).
- **Приоритет:** средний. Реальный пробел для тактических боёв.
- **План:** отложить → `На_будущее.md` (слой миниатюр/токенов — отдельный спек-тикет).

### M6. Печать через браузер не даёт контроль над полями/ориентацией — [Мастер, Печать]
- **Файл:** `MapEditorPage.tsx:1276–1383`
- PNG —.rectangle canvas. Печать через `Ctrl+P` браузера: браузер сам решает поля, ориентацию, масштаб. Карта может уехать на 2 листа без «склейки». Нет `@media print` стилей для `.map-editor` (в `index.css` или `canvas.css`).
- **Приоритет:** средний.
- **План:** CSS `@media print`: скрыть тулбары/панели, canvas → `width: 100%; height: auto`, `page-break-inside: avoid`.

### M7. Нет «истории сидов» — мастер не помнит, какой сид давал一个好的 остров — [Мастер]
- **Файл:** `MapEditorPage.tsx:478–480`
- `rollSeed()` генерирует случайный сид. Если мастер сгенерировал красивый остров, но потом передумал и сгенерировал другой — **старый сид потерян** (сохраняется в `genParams.seed`, но если он переключился на другой seed и сгенерировал — старый можно ввести вручную, но он не запоминается как «нравится»).
- **Приоритет:**很低.
- **План:** список «избранных сидов» в localStorage; позже.

### M8. Карта не показывает «где я за столом» (последняя позиция камеры) — [Мастер]
- **Файл:** `MapEditorPage.tsx:182, 1449–1464`
- Камера: `fitCamera()` при открытии — вписывает всю карту. Позиция камеры **не сохраняется** в `localStorage` или на сервере. Если мастер за столом зумнул на B12 и открыл карту заново — камера вписывается заново, приходится зумить заново.
- **Приоритет:** средний.
- **План:** сохранять `cam` в `localStorage` по `map.id`; восстанавливать при открытии; кнопка «Вписать» уже сбрасывает (P0-4).
