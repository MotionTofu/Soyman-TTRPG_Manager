# WeGot — техническое описание существующего редактора карт (факт, без рефакторинга)

Дата фиксации: 2026-09-20. Источники: `client/src/pages/MapEditorPage.tsx` (~4022 строки),
`client/src/maps/grid.ts`, `render.ts`, `generate.ts`, `dungeon.ts`, `mapExchange.ts`, `mapExport.ts`,
`mapTypes.ts`, `server/src/routes/maps.ts`, `mapsValidation.ts`, `server/src/db/db.ts` (таблица `maps`).

## 1. Общая архитектура

Стек: React + TypeScript + Vite (клиент `client/`), Express + better-sqlite3 (сервер `server/`).
Отдельного stores-слоя (Zustand/Redux) у карт нет. Весь редактор — один компонент-контроллер
`MapEditorPage` + чистые модули `client/src/maps/*`.

Основные модули:
- `client/src/pages/MapEditorPage.tsx` — UI, локальный state, камера, ввод (мышь/тач/колесо/хоткеи),
  история undo/redo, автосейв, генераторы, экспорт, привязки, модалки.
- `client/src/maps/grid.ts` — чистая геометрия сеток, без React/DOM.
- `client/src/maps/render.ts` — типы слоя клеток/объектов, parse/serialize blob, Canvas 2D рендер,
  миниатюры.
- `client/src/maps/generate.ts` — детерминированный value-noise генератор суши.
- `client/src/maps/dungeon.ts` — данж-генератор (порт donjon-алгоритма) + починка связности.
- `client/src/maps/mapExchange.ts` — JSON выгрузка/загрузка (`soyman-map/1`), чистые функции.
- `client/src/maps/mapExport.ts` — сборка PNG-экспорта с легендой, чистые функции от снапшота.
- `client/src/maps/mapTypes.ts` — `MapSummary`/`MapFull`, пресеты масштабов, перевод ошибок API.
- `server/src/routes/maps.ts` — CRUD, трим blob под ресайз, чистка секретного слоя игрокам.
- `server/src/routes/mapsValidation.ts` — чистая валидация (без импорта db), версии blob v1–v4.

State карты: локально в `MapEditorPage` — `map: MapFull | null` (мета) + `cells: MapCells`
(рабочие клетки/объекты). Зеркало для императивных canvas-хендлеров — `cellsRef`.
Камера `cam {scale, ox, oy}` отдельно. История — `pastRef`/`futureRef` (массивы `MapCells`).
Чтение карты — мимо кэша слоя данных (`readOnce('/maps/:id')`), чтобы чужие правки
не ложились поверх несохранённых мазков; запись — `write.put`.

Связь UI → state → renderer: React-state меняется (`setCells`/`setCam`/hover/ruler/...),
`useEffect`-кадр читает снапшот и рисует `renderMap(ctx, ...)` заново (immediate mode,
ретенированной сцены нет). Canvas-хендлеры пишут через `cellsRef.current = draft; setCells(draft)`.

Библиотека рендеринга: голый Canvas 2D API (`getContext('2d')`), DPR через
`ctx.setTransform(dpr,0,0,dpr,0,0)`, ручное преобразование `X = ox + wx*scale`.
WebGL/DOM/SVG/игровой движок — не используются.

ECS / scene graph: нет. Своя объектная модель: `MapCells`
(`terrain: Map<string,string>`, `roads/rivers: Set<string>`, массивы `labels/rooms/doors/traps/markers`,
`start/finish`), сериализуемая в JSON-blob одной строкой.

Текстовая схема (факт):

```text
Toolbar/Panels/Canvas events (MapEditorPage)
  ↓  paintAt / placeObject / mutateObjects / moveObjTo / generate / import
cells: MapCells (useState + cellsRef) + map: MapFull (meta)
  ↓  useEffect [map, cells, cam, hover, ruler, selected, ...] → renderMap(...)
Canvas 2D renderer (maps/render.ts) — immediate redraw, culling видимых клеток
  ↓  AUTOSAVE 800ms → PUT /api/maps/:id {cells, thumbnail, genParams}
SQLite maps.cells (TEXT blob v1–v4) + meta columns
```

## 2. Модель данных карты

Клиентские типы (`maps/mapTypes.ts`, `maps/render.ts`):

```ts
type MapGrid = "square" | "hex";
type MapScale = "planet" | "continent" | "country" | "region" | "settlement" | "locality";

interface MapSummary { // строка списка GET /api/maps (мета без клеток)
  id: number; name: string; grid: MapGrid; scale: MapScale;
  width: number; height: number; cell_lore: string;
  seed: number; sea: number; mountains: number; forest: number;
  thumbnail: string | null; player_visible: number; parent_map_id: number | null;
  created_at: string; updated_at: string;
}
interface MapFull extends MapSummary { cells: string; } // + blob клеток

interface MapCells { // рабочая in-memory модель редактора
  terrain: Map<string, string>; // "x,y" -> код террейна; нет записи = равнина
  roads: Set<string>;           // "x,y" с дорогой поверх террейна
  rivers: Set<string>;          // "x,y" с рекой поверх террейна, под дорогами (v4+)
  labels: MapLabel[];           // v2+
  rooms: MapRoom[];             // v3+
  doors: MapDoor[];
  traps: MapTrap[];
  markers: MapMarker[];         // v4+
  start: { x: number; y: number } | null;
  finish: { x: number; y: number } | null;
}
interface MapLabel { x: number; y: number; text: string; }            // ≤200, текст ≤64
interface MapRoom { x: number; y: number; w: number; h: number; type: MapRoomType; name: string; }
type MapRoomType = "empty"|"barracks"|"temple"|"treasury"|"prison"|"lab";
interface MapDoor { x: number; y: number; edge: "n"|"s"|"e"|"w"; kind: MapDoorKind; secret: boolean; pair: string | null; }
type MapDoorKind = "arch"|"door"|"locked"|"trapped"|"secret"|"portc";
interface MapTrap { x: number; y: number; kind: "pit"|"arrow"|"gas"|"glyph"; }
interface MapMarker { x: number; y: number; kind: "chest"|"altar"|"city"|"village"|"camp"|"metro"|"battle"|"obelisk"; }
type MapGrid = "square" | "hex"; // Grid — только enum типа сетки, отдельной структуры нет
// Terrain — строковый код (18 значений, см. §5), отдельной структуры нет.
// Asset — отсутствует как сущность: ссылок на изображения в модели карты нет вообще.
```

Сервер (`routes/mapsValidation.ts`, `db.ts`): таблица `maps`
`(id, name, grid CHECK square/hex, scale CHECK 6 значений, width, height,
cell_lore, seed, sea, mountains, forest, cells TEXT, thumbnail TEXT,
player_visible, parent_map_id REFERENCES maps(id), created_at, updated_at)`.
Плюс `map_bindings (map_id, target_type setting/campaign/location, target_id)`.

Что сохраняется в файле карты: ОДНА строка SQLite = мета-колонки + `cells` TEXT.
`cells` — JSON-blob `{v: 1|2|3|4, cells: {"x,y": terrain}, roads: ["x,y"], rivers?, labels?, rooms?, doors?, traps?, markers?, start?, finish?}`.
Равнина (`plain`) не пишется. Старший формат диктуется содержимым:
маркеры/реки → v4, объекты → v3, подписи → v2, иначе v1 (`serializeCells`,
`render.ts:1246`). Пресеты масштаба: `MAP_SCALE_PRESETS` (напр. continent 40×30 «100 км»);
лимиты поля 8–100 по стороне, капы: labels 200, rooms 100, doors 400, traps 300, markers 300.

## 3. Система координат

- World coordinates: абстрактные «мировые единицы» = шаг клетки. Квадраты: клетка `(x,y)` =
  квадрат `[x,x+1]×[y,y+1]`, центр `(x+0.5, y+0.5)`. Гексы: pointy-top, раскладка odd-q,
  центр `(sqrt(3)·(x + 0.5·(y&1)), 1.5·y)` (`cellCenter`, `grid.ts:41`).
- Screen coordinates: `sx = ox + wx*scale`, `sy = oy + wy*scale`. Камера `cam {scale, ox, oy}`.
- Grid coordinates: целые `(x, y)`, `0 ≤ x < width`, `0 ≤ y < height`; человеческая подпись `A1…`
  (`coordLabel`: колонки буквами A..Z, AA.., строки с 1).
- Размер клетки: фиксированного px-размера нет; мировой шаг = 1. Экранный размер = `scale` px.
- Карта без grid: невозможна. `grid` обязателен (`square|hex`, смена только через очистку),
  чекбокс скрывает лишь отрисовку линий (`showGrid`, `localStorage maps.showGrid`).
- Zoom: `scale` 4..240 px/ед. Колесо (нативный wheel-лисенер, `Math.pow(1.0015, -deltaY)`,
  зум к курсору), кнопки/хоткеи `+/−` (×1.25 к центру), `0` — вписать. Автофит при открытии
  по `worldBounds` + pad 24.
- Camera/pan: `ox/oy` в px. Средняя кнопка, `Space`+ЛКМ, тач-два-пальца/pinch; миникарта-прыжок;
  позиция запоминается в `localStorage maps.cam.<id>` (debounce 500мс), «Вписать» стирает память.
- screen → world: `(wx,wy) = ((rx-ox)/scale, (ry-oy)/scale)` (`toWorld`, `MapEditorPage.tsx:1971`).
- world → grid: `pixelToCell`: квадраты — `floor`, гексы — ближайший центр среди 3×3 кандидатов
  вокруг приближения (`grid.ts:68`). Вне поля — `null`.

## 4. Рендеринг

- Чем рисуется: один `<canvas>`, голый Canvas 2D. Отдельного движка нет.
- Технология: Canvas 2D / immediate mode. Изображения: не используются вообще
  (только `drawImage` склейки при PNG-экспорте и `toDataURL` для миниатюр).
  Террейн — `fillStyle` заливка + процедурные векторные мотивы (`drawTerrainMotif`:
  волны, сосны, шевроны, точки — `render.ts:106`).
- Batching: группировка по террейну (`byTerrain`: один `fillStyle` на все клетки кода за проход);
  дороги/реки — один `beginPath` на весь оверлей (`traceOverlayLine`); сетка — один проход.
  Текстурных атласов/слоёв-canvas нет.
- Culling: есть, ручной. Видимый диапазон `vx0..vx1/vy0..vy1` из камеры + запас 1 клетка;
  красятся только расписанные+видимые клетки; поле квадратов заливается одним `fillRect`,
  гексы — по видимым. Объекты/подписи/ховер — с проверкой `inView`.
- Render loop: нет постоянного цикла/`requestAnimationFrame`-рендера. Перерисовка —
  `useEffect` по `[map, cells, cam, showGrid, showCoords, hover, ruler, selected,
  rectPreview, previewAsPlayer, wallDraft, wallLive, tool, brushSize, wallLineMode]`.
  Мазки pointermove коалесцируются через `requestAnimationFrame` (`flushPaint`), но сам рендер —
  синхронный в эффекте. Отдельных dirty-rect нет — всегда полный кадр.
- Большие карты: жёсткий кап 100×100 (10 000 клеток). Разреженное хранение
  (пустые клетки не хранятся). Пороговые отключения деталей: мотивы террейна `scale≥16`,
  объекты `scale≥10`, глифы/текст `≥14`, координаты `≥18`, подписи `≥12`.
  Кэш миниатюры (троттлинг 2.5с). PNG-экспорт синхронный — на 100×100@48–64 морозит UI
  на секунды (зафиксировано в коде, Д-13).
- Рендерится ли вся карта постоянно: нет rAF-цикла; рендерится видимая часть по каждому
  изменению state. Невидимые клетки пропускаются, но сериализация/клонирование state —
  всегда целиком (см. §12).

## 5. Tile system

- Размер тайла: равен клетке всегда. Отдельного пиксельного тайла/спрайта нет.
- Хранение tile map: разреженный `Map<"x,y", terrainCode>`; отсутствие = `plain`.
  Оверлеи `roads`/`rivers` — `Set<"x,y">` поверх террейна.
- Один тайл = одна клетка: да, строго 1:1. Подклеточной точности у террейна нет.
- Несколько tile layers: нет. Один слой террейна + два overlay-сета (реки под дорогами).
  Настоящих именованных слоёв нет.
- Autotiling: нет. Bitmask / Wang tiles / terrain-blending: нет. Переходы не генерируются;
  «мост» читается лишь порядком отрисовки (река шире+подложка, дорога сверху).
- Rotation/mirroring тайлов: нет (мотивы рисуются одинаково).
- Соседство: `neighbors()` — 4-связность (квадраты) / 6-связность odd-q (гексы).
  Используется для заливки, линий дорог/рек (сегменты к соседям «вперёд»), обводки комнат
  (сегмент периметра рисуется, только если за ним `wall` или край карты).
  Террейнов 18: `deep_water, shallow_water, plain, forest, hills, mountains, desert, ice,
  swamp, lava, acid, poison, wall, stone, wood, earth, darkness, necro`.
  Генератор ставит только воду/равнину/горы/лес; `wall` ставят данж/инструменты,
  лава/кислота/яд/полы/тьма — только руками.

## 6. Объекты

Размещаемые объекты — клеточно-привязанные записи (свободного размещения нет):

| Тип | position | size | rotation/scale/z-index/layer/asset |
|---|---|---|---|
| Room | `x,y` клетки верхнего-левого угла | `w,h` в клетках | нет / нет / нет / нет / нет; `type` (тинт) + `name` |
| Door | `x,y` клетки + `edge n/s/e/w` (ребро; определяется долей позиции клика внутри клетки) | ребро (плашка 0.72×0.34 клетки) | нет / нет / нет / нет / нет; `kind`, `secret`, `pair` |
| Trap | `x,y` клетки (центр через `cellCenter`) | 0.6 клетки | нет / нет / нет / нет / нет; `kind` |
| Marker | `x,y` клетки | 0.6 клетки | нет / нет / нет / нет / нет; `kind` (8 видов) |
| Start/Finish | `x,y` клетки, синглтоны | ~0.76 клетки / клетка | нет |
| Label | `x,y` клетки + `text` | текст поверх | нет |

Свободно вне grid: нет. Всё квантуется к клетке (`pixelToCell`); полилиния стен —
к `traceLineCells`, вершины опционально к центру клетки (`wallSnap`, дефолт вкл).
Порядок отрисовки фиксирован кодом: террейн → реки → дороги → комнаты (тинт/номера/обводка
по стенам) → двери → ловушки (только мастер) → маркеры → старт/финиш → сетка →
координаты → подписи → подсветка/линейка/черновики. Пер-объектных z-index нет;
выбранный подсвечивается чернильной обводкой (`selectedKey`: `door:N`, `trap:N`,
`marker:N`, `room:N`, `start`, `finish`).

## 7. Слои

Именованных слоёв нет. Слоистая модель отсутствует как сущность: нет hide/lock per-layer,
нет вложенности, нет порядка, задаваемого пользователем. Есть только:
- фиксированный порядок отрисовки (см. §6, зашит в `renderMap`);
- два тумблера отрисовки: `showGrid`, `showCoords` (persist в localStorage);
- фильтр `playerView` (мастер-тумблер «взгляд игрока»; игроки всегда в нём):
  секретные двери скрыты, `trapped` показана как обычная, ловушки скрыты,
  тип комнат отдан как `empty` (серверная чистка `stripCellsForPlayer` — скрытое
  не покидает сервер);
- `player_visible` — флаг целой карты, не слоя;
- при ресайзе-ужимке кроп по правилу «снаружи пропадает», комната за краем уходит целиком.

## 8. Редактирование

- Selection: одиночный выбор (`ObjSel`: door/trap/marker/room/start/finish + индекс).
  Хит-тест `hitObject`: двери по ближайшему ребру (только квадраты) → ловушки →
  маркеры → старт/финиш → комнаты (сверху вниз по массиву). Любая замена `cells`
  сбрасывает выбор (`useEffect [cells]`). Мультиселекта нет.
- Transform/drag/resize/rotate: drag-перемещение выбранного живьём из снапшота начала
  (`moveObjTo`): ловушки/маркеры/старт/финиш — на новую клетку; комнаты — со сдвигом,
  кламп в поле; двери — жёсткий дельта-сдвиг пары (`pair`) + новое ребро у тащимой.
  Порог 6px отделяет клик (панель) от drag. Resize/rotate ручек нет; комнату меняют
  удалением/созданием, тип/имя — через панель.
- Copy/paste/duplicate объектов: нет. Есть дублирование целой карты (`duplicateMap`
  → POST `/maps` с теми же blob+превью, навигация на новую). Ctrl+C/V в редакторе нет.
- Snapping: всегда к клетке; отдельный toggle только у полилинии стен (`wallSnap`).
- Brushes: `paintStroke` по `brushCells(grid, cx, cy, size 1|2|3)`; метрика —
  Чебышев (квадраты) / hex-distance через odd-q→cube (гексы). Кисть террейна, даб стен
  (`wall` как зафиксированная краска), оверлеи дорога/река, ластик
  (террейн+оба оверлея), правая кнопка — временный ластик (`eraseOverrideRef`),
  `Alt+клик` — пипетка (террейн; с активным оверлеем — снять его с клетки).
  `fill` — flood fill связной области одного террейна (4/6-связность).
  `shape` — прямоугольник: комната (→ модалка создания) / террейн / дорога / река /
  стены / ластик одним шагом. Стены линией — полилиния вершин + `traceLineCells`
  (суперкавер сэмплированием, шаг полклетки) + Enter/дабл-клик финиш.
  Линейка — замер (не мазок, в историю не идёт): евклид на квадратах, шаги на гексах,
  плюс метры через `parseCellLore(cell_lore)`. Подписи — модалка на клетку
  (создать/править/удалить). Двери/ловушки/маркеры/старт/финиш кликом ставятся
  сразу (каждый клик — undo-шаг), правятся через панели (вид, секретность, имя/тип).

## 9. Undo / Redo

Механизм: стейт-снапшоты, не command pattern и не патчи. `pastRef: MapCells[]`,
`futureRef: MapCells[]`, глубина 50 (`UNDO_DEPTH`). `cloneCells` — глубокое
копирование (новые `Map`/`Set`/массивы). Мазок целиком — один шаг:
`beginStroke` (снимок `before`) → мазки мутируют draft → `endStroke` → `pushHistory(before)`
если `changed`. Точечные операции — снимок+применение+push (`mutateObjects`,
`paintStroke`+`floodFill`, шейпы, стены линией, импорт, генерация, ресайз-кроп,
панели объектов). Undo: `pop past → push clone(current) в future → setCells(prev)`.
Redo симметрично. История эфемерна (не переживает перезагрузку — прямо сказано
в диалогах генерации). В историю не идут: камера, hover, линейка, тумблеры вида,
панели. Хоткеи: `Ctrl+Z`, `Ctrl+Shift+Z` / `Ctrl+Y` (по `code`, в полях ввода молчат).

## 10. Сохранение

Формат: JSON (TEXT-колонка `cells` + JSON-документ обмена `soyman-map/1`).
Серверный PUT принимает `{cells, thumbnail, seed/sea/mountains/forest, name/scale/...}`.
Автосейв: debounce 800мс; пропуск при равенстве `serializeCells(cells)+"|"+genParams`
последнему сохранённому (загрузка и undo-в-ту-же-точку ничего не шлют);
защита от гонки overlapping PUT по `seq` (побеждает поздний мазок);
ретрай вручную при `error` + `beforeunload`-сторож. Битый серверный blob:
пустая карта + плашка, автосейв поверх блокирован до явного разрешения (P1-7).
Ресайз-ужимка кропает blob клиент+сервер (`trimCellsTo` на сервере дублирует правило).

Пример сохранённой карты (схема; значения иллюстративные):

```json
{
  "format": "soyman-map/1",
  "name": "Пример",
  "grid": "square",
  "scale": "continent",
  "cell_lore": "100 км",
  "width": 40, "height": 30,
  "seed": 7, "sea": 55, "mountains": 12, "forest": 30,
  "cells": "{\"v\":4,\"cells\":{\"3,5\":\"forest\",\"4,5\":\"wall\"},\"roads\":[\"3,5\",\"3,6\"],\"rivers\":[],\"labels\":[{\"x\":3,\"y\":5,\"text\":\"Тракт\"}],\"rooms\":[{\"x\":2,\"y\":2,\"w\":4,\"h\":3,\"type\":\"barracks\",\"name\":\"\"}],\"doors\":[{\"x\":3,\"y\":2,\"edge\":\"n\",\"kind\":\"door\",\"secret\":false,\"pair\":null}],\"traps\":[],\"markers\":[{\"x\":5,\"y\":5,\"kind\":\"city\"}],\"start\":{\"x\":2,\"y\":2},\"finish\":null}"
}
```

- Asset URLs: не сохраняются (их нет в модели).
- IDs: per-map `id` (integer), `map_bindings.id`; per-объектных стабильных ID нет —
  адресация индексами массивов (эфемерны), пары дверей — строка `pN` (`pairSeq`).
- Versioning: `v: 1|2|3|4` внутри blob + `format: "soyman-map/1"` у обменного файла.
- Backward compatibility: старые blob читаются как были (недостающие поля —
  дефолты/пустые); новые поля в старом конверте — ошибка, а не дроп
  (`rivers/markers needs v4`); клиентский парсер роняет битые записи поштучно
  (не весь blob), серверный валидатор — строго с текстом ошибки;
  `cellsBlobStatus` отличает `ok/corrupt`.

## 11. Asset system

Отсутствует. В редакторе карт нет загрузки изображений/тайлов/токенов/объектов:
нет asset registry, нет asset packs, нет категорий, нет метаданных ассетов.
Карта — чисто процедурный вектор (заливки `MAP_TERRAIN_FILL` + рисованные мотивы),
объекты — фигуры кодом (`render.ts:800–1147`). Единственные «картинки» в контуре:
`thumbnail` (сервер хранит PNG data URL `data:image/png;base64,…`, ≤300 000 символов,
пишется только `canvas.toDataURL`, валидируется префиксом/base64 — P0-6) и
PNG-экспорт (`mapExport.ts`: поле + легенда + линейка). Точечная догрузка превью:
`GET /:id/thumbnail` (список превью не отдаёт — P0-2). Игрокам превью не отдаётся
вообще (иначе утекали бы секреты через список). Смежный, но отдельный контур —
`LocationMap` (подложка `map_image_url` у локаций) и `rasterAssets` общего UI;
к редактору карт они не подключены.

## 12. Производительность

Зафиксированные фактами ограничения и оптимизации:

- Число объектов: капы валидации — rooms 100, doors 400, traps 300, markers 300,
  labels 200. Парсинг роняет лишнее/битое поштучно с капами.
- Размеры карты: 8–100 по стороне (макс. 10 000 клеток). 100×100@48–64 в PNG-экспорте
  синхронно морозит UI на секунды (Д-13, кнопка дизейблится, сборка уезжает в таймер 30мс).
- Memory: каждая клетка мазка — `cloneCells` всего `MapCells` (Map+2 Set+5 массивов);
  pointermove-частоту гасит rAF-коалесцирование (`pendingPaintRef` + `flushPaint`),
  но сам клон — полный. История — до 50 полных клонов (верхняя оценка при 10k клеток
  и полных массивах — десятки МБ, точная цифра не замерялась).
- Texture loading: нет (текстур нет).
- Rendering: culling видимых + пороги детализации по `scale` (см. §4) + группировка
  по террейну + один проход сетки/оверлеев. Нет виртуализации тайлов, нет offscreen-слоёв,
  нет инкрементального рендера — каждый кадр полный.
- Serialization: шлётся весь blob целиком каждый автосейв (патчей нет); троттлинг превью
  2.5с (`thumbCacheRef`), иначе `null` → сервер `COALESCE` оставляет старое превью.
  Эталон сравнения — нормализованная сериализация (иначе ложное «изменено»).
- Существующие оптимизации списком: culling +1 клетка; пороги `scale` 10/12/14/16/18;
  батчинг по террейну/оверлеям; rAF-коалесцирование мазков; пропуск сейва при равенстве;
  seq-защита от гонки; троттлинг миниатюр; список без thumbnails + точечная догрузка;
  запоминание камеры (не пересчитывать фит); `readOnce` мимо кэша (не оптимизация
  скорости, а защита от перезаписи).

## 13. Существующие инструменты карты

`PaintTool` (`MapEditorPage.tsx:63`): `brush | fill | eraser | picker | road | river |
wall | shape | ruler | label | select | door | trap | chest | altar | marker | start | finish`
(18; размер кисти 1|2|3 отдельно). Плюс режимы/панели (не `PaintTool`):
генератор суши / подземелья, починка связности, PNG/JSON обмен, настройки/ресайз,
дубль/архив, привязки, показ игрокам, превью глазами игрока, миникарта.

- Select (V): клик — выбор объекта (хит-тест §8) → drag-перемещение или панель правки;
  по пустому — drag-прямоугольник → модалка создания комнаты. Delete — удалить
  (пару дверей — целиком). Мультиселекта нет.
- Pan: средняя кнопка / Space+ЛКМ / тач; Zoom: колесо к курсору, кнопки, `+/-/0`.
- Tile Brush / кисть (B): `paintStroke` текущем террейном по `brushCells(size)`.
  Футпринт 2/3 подсвечивается целиком (`hoverCells`).
- Eraser (E) + ПКМ-ластик: чистка террейна (→ plain, запись удаляется) + дорог + рек
  с клетки/футпринта; инструмент не переключает.
- Picker (I) / Alt+клик: взять террейн клетки (с оверлеем — включить его инструмент);
  с активным road/river Alt+клик снимает оверлей точечно.
- Fill (G): flood fill связной области одного террейна.
- Road (R) / River (N): оверлеи поверх любого террейна (река и поверх дороги);
  рисуются линией по центрам соседних клеток; одиночка — точкой.
- Wall (W): даб — кисть с зафиксированной краской `wall`; режим линии —
  полилиния вершин (снеп к центру, `wallSnap`) + Enter/дабл-клик финиш →
  `traceLineCells` в `wall` одним undo-шагом.
- Shape (U): drag-прямоугольник; содержимое на выбор: room (→ модалка) / terrain /
  road / river / wall / eraser. Тач — два тапа по углам.
- Ruler (M): замер A→B (`rulerMeasure` + метры через `cell_lore`); в историю не идёт;
  Esc сбрасывает.
- Label (T): клик → модалка текста (≤64 симв., ≤200 подписей) создать/править/удалить.
- Door (D): клик — обычная дверь на ближайшее ребро (квадраты only); панель —
  вид (6), секретность, удаление (пара целиком).
- Trap (L): клик — ловушка последнего вида (4); панель — вид/удаление.
- Chest (C) / Altar (A): клик — маркер-сундук / алтарь.
- Marker (K): клик — маркер выбранного вида (город/деревня/лагерь/метрополия/битва/обелиск).
- Start (S) / Finish (F): клик — замена синглтона.
- Генератор суши: value-noise fBm 4 октавы + радиальный спад (остров), сид/море/горы/лес;
  ставит воду/равнину/горы/лес; подписи/объекты не переносит; целый один undo-шаг;
  с подтверждением по непустой карте.
- Генератор подземелий (квадраты only): комнаты + MST-коридоры + петли + двери
  по «правилу горлышка» (узкий проход 1–2) с группировкой/парами + старт/финиш/ловушки;
  материализуется стенами `wall`; детерминирован (mulberry32); пресет «быстрый данж».
- Починка связности: BFS-достижимость от старта + L-коридоры к изолированным
  (ручная — без сноса дверей, только расчистка `wall`).
- Мини-карта: превью всего поля + прыжок кликом. PNG-экспорт: плотность 16–64,
  сетка/координаты/легенда/вид игрока — опционально. JSON: экспорт/импорт
  `soyman-map/1` только в карту того же размера/сетки.

## 14. Особо важно — куда теоретически лечь расширениям (без реализации)

- Terrain Materials (напр. «трава с вариациями/текстурами» поверх кода террейна):
  потребуется изменение. Причина: террейн — плоский строковый код с одной заливкой
  и одним мотивом (`MAP_TERRAIN_FILL` + `drawTerrainMotif` switch); seed-вариантности,
  подслоёв и полей материала в `cells` нет; рендер группирует строго по коду.
  Материал пришлось бы добавлять новым полем/каналом и ветвить батчинг и легенду.
- Auto Transitions (берега, кромки биомов по соседству): потребуется изменение.
  Причина: соседство считается (`neighbors`), но рендер красит клетки независимо
  (нет edge-маски, нет bitmask/Wang, нет прохода по границам кроме дорог/рек/комнат);
  понадобился бы новый краевой проход + правила переходов на каждый террейн.
- Scatter Areas (зоны с плотностью/распределением декора): потребуется изменение.
  Причина: все записи — точечные/поклеточные без понятий «зона», «плотность», «seed зоны»;
  blob v1–v4 таких сущностей не знает (валидатор режет неизвестное), генераторы
  детерминированы от глобального сида и не хранят зоны.
- Spline Paths (кривые дороги/реки/маршруты как объекты): конфликтует с архитектурой
  частично (как хранение) / потребуется изменение (как рендер). Причина: дороги/реки —
  множества клеток `Set<"x,y">` без порядка и контрольных точек; кривую негде хранить
  (нет массива точек, нет ширины/слоя пути), растеризация идёт по соседству клеток,
  а не по параметрической кривой. Хранение сплайна — новая сущность v5+.
- Procedural Presets (пресеты «лес/деревня/озеро одной кнопкой»): легко (как операции).
  Причина: прецеденты есть — `generateCells`/`generateDungeon`/`fixMapConnectivity` уже
  являются чистыми функциями `params → MapCells/патч` + один undo-шаг + подтверждение
  по непустой карте; новый пресет ложится тем же путём без смены модели/рендера.
  Ограничение: пресет не может хранить «параметрический рецепт» — только применить
  результат (полей рецепта в blob нет).
- Asset Packs (паки спрайтов/токенов для клеток/объектов): конфликтует с архитектурой.
  Причина: в модели нет `asset reference` вообще (ни URL, ни ID, ни пивот/масштаб/поворот);
  рендер не грузит изображений; валидатор разрешает только закрытый список кодов;
  серверная чистка игрокам оперирует кодами, не ассетами. Пак потребовал бы: новую
  сущность ассета + ссылку в клетке/объекте + загрузчик/кэш текстур + атлас/батчинг +
  новую версию blob + правила стриппинга секретов для картинок.

## 16. Итоговая схема и архитектурные ограничения

Компактная схема существующего:

```text
MapEditorPage (state: map, cells, cam, tool, history[50], refs)
  ├─ grid.ts (чистая математика: cell ↔ world ↔ screen)
  ├─ render.ts (parse/serialize + immediate Canvas2D, culling, пороги scale)
  ├─ generate.ts / dungeon.ts (чистые генераторы → MapCells)
  ├─ mapExchange.ts (JSON soyman-map/1) / mapExport.ts (PNG+легенда)
  └─ PUT /api/maps/:id (debounce 800ms, seq-guard, thumb-throttle)
       └─ SQLite maps(id, meta…, cells TEXT v1–v4, thumbnail) + map_bindings
```

Самые сильные архитектурные ограничения (факты, без предложений):

1. Один тайловый слой + плоский код террейна: нет подслоёв, переходов, вариаций,
   поворота/зеркала; всё расширение упирается в смену схемы blob и батчинга.
2. Нет слоёв как сущностей: порядок зашит, hide/lock/прозрачность/маски/эффекты
   некуда вешать.
3. Объекты строго клеточные: нет свободных координат, размера в px, поворота,
   масштаба, z-index, ссылок на ассеты; сплайны/зоны/токены негде хранить.
4. Нет ассет-контура: рендер не умеет в изображения; любой пак спрайтов —
   новая подсистема (загрузка, кэш, атлас, стриппинг).
5. Снапшотная история и полно-blob сейвы: цена операции растёт с картой;
   долгоживущих веток/рецептов/параметрических зон нет.
6. Монолит `MapEditorPage` (~4k строк): состояние, ввод, камера, история, сеть,
   генераторы и экспорт живут в одном компоненте; чистая логика вынесена лишь
   частично (`maps/*`), что делает любое расширение правкой контроллера.
7. Версионирование аддитивное без миграций данных: старые клиенты/файлы понимают
   только свой конверт; новые сущности = новая версия + каскад правок
   клиент/валидатор/рендер/стриппинг/обмен.
