# SoyMan Fantasy Punk Design Codex v1

## 1. Общая идея

SoyMan выглядит не как обычное веб-приложение с наложенной сверху гранж-текстурой.

Визуальная метафора:

**панк-зин + фэнтезийная карточная игра + рабочий игровой лист, который живёт вместе с персонажем.**

Интерфейс должен ощущаться:

* рукотворным;
* дерзким;
* немного неправильным;
* комиксовым;
* карточным;
* тактильным;
* но при этом очень быстрым в игре.

Ключевой принцип:

> **Функциональный UI остаётся чистым. Хаос живёт вокруг него.**

Нельзя жертвовать читаемостью HP, ресурсов, заклинаний, кнопок или навигации ради стилизации.

---

# 2. Иерархия визуальной выразительности

Интенсивность стиля зависит от типа элемента.

### Уровень 0 — информация

Практически без эффектов.

Используется для:

* основного текста;
* чисел;
* HP;
* AC;
* характеристик;
* значений ресурсов;
* длинных описаний;
* форм.

Разрешено:

* характерная типографика;
* цвет;
* тонкие разделители.

Запрещено:

* datamosh;
* сильные аберрации;
* тяжёлый halftone;
* шум поверх букв.

---

### Уровень 1 — controls

Лёгкий punk-акцент.

Используется для:

* кнопок;
* input;
* select;
* toggle;
* menu;
* quick controls.

Разрешено:

* срезанные углы;
* грубая рамка;
* небольшой marker stroke;
* 1 декоративный штрих;
* очень слабый halftone.

Controls должны оставаться очевидно интерактивными.

---

### Уровень 2 — surfaces / navigation

Умеренная стилизация.

Используется для:

* панелей;
* секций;
* вкладок;
* wizard navigation;
* карточек персонажей;
* модалок.

Разрешено:

* угловые украшения;
* бумажные края;
* крупные цветовые пятна;
* marker underline;
* chromatic offset;
* halftone background.

---

### Уровень 3 — content cards

Сильная стилизация.

Используется для:

* классов;
* видов;
* предметов;
* подклассов;
* тематических карточек.

Здесь разрешён полный Fantasy Punk:

* halftone;
* аберрации;
* коллаж;
* граффити;
* marker;
* бумага;
* кислотные заливки;
* контролируемый datamosh;
* иллюстрация как главный акцент.

---

### Уровень 4 — hero / empty / promotional

Максимальная выразительность.

Используется для:

* пустой библиотеки;
* onboarding;
* декоративных splash-состояний;
* больших иллюстраций.

Здесь можно позволить визуальный беспредел, пока текст остаётся читаемым.

---

# 3. Палитра

## Базовые цвета

### Paper

Основной светлый фон:

`#E8E4DA`

Не белый. Немного грязная, тёплая бумага.

Дополнительная поверхность:

`#D8D3C8`

Светлая приподнятая поверхность:

`#F2EFE7`

---

### Ink

Основной:

`#171717`

Не абсолютный `#000000`, чтобы интерфейс сохранял печатное ощущение.

Вторичный:

`#56534F`

Третичный:

`#817C75`

---

## Главные акценты

### Acid Yellow

`#F3FF3A`

Главный энергетический цвет.

Использование:

* active marker;
* selection;
* подчёркивание;
* крупное цветовое пятно;
* иногда primary CTA.

---

### Punk Magenta

`#FF3E91`

Второй главный акцент.

Использование:

* контрастные пятна;
* состояния;
* иллюстративные элементы;
* chromatic offsets;
* альтернативный CTA.

Жёлтый и magenta могут меняться композиционными ролями.

Они не жёстко означают primary/secondary.

---

## Системные цвета

### Danger

`#D92D3F`

Грязный красный.

Для:

* удалить;
* потеря данных;
* критическая ошибка.

---

### Success

`#58D66A`

Ядовито-зелёный, но не неоновый на всём экране.

---

### Info / Sync

`#3ED6D0`

Cyan используется редко:

* sync;
* network;
* технические статусы.

Не превращать интерфейс в cyan-tech UI.

---

# 4. Правило цвета

На одном обычном экране одновременно активно:

* paper;
* ink;
* один основной кислотный акцент;
* второй акцент локально;
* semantic color только если нужен.

Не использовать:

`yellow + magenta + cyan + green + red`

одновременно во всех компонентах.

Стиль должен быть ярким, но не выглядеть как RGB-тест монитора.

---

# 5. Типографика

Три уровня.

## UI Font

Максимально читаемый гротеск.

Используется для:

* body;
* controls;
* labels;
* характеристики;
* HP;
* inventory;
* длинные тексты.

Требования:

* хорошая кириллица;
* высокая читаемость на телефоне;
* нормальные цифры;
* плотность без ощущения corporate UI.

---

## Display Font

Характерный грубый заголовочный.

Используется для:

* имя персонажа;
* класс;
* заголовки разделов;
* экранные hero titles;
* крупные числа уровня.

Допустимо:

* condensed;
* rough;
* distressed;
* comic/zine character.

Нельзя:

* длинные абзацы;
* мелкие labels.

---

## Handwritten Layer

Отдельный декоративный стиль.

Визуально:

* шариковая ручка;
* много раз проведённая линия;
* маркер;
* punk scribble.

Используется для:

* подчёркиваний;
* стрелок;
* микро-комментариев;
* декоративных цифр;
* коротких эмоциональных акцентов.

Не используется для критической информации.

---

# 6. Типографическая иерархия

Пример:

```text
МОРДЕКАЙ                ← display
Варвар • 7 уровень      ← UI medium

17 / 28                  ← UI bold / numeric
Хиты                     ← UI small

БЕЗУМИЕ!                 ← handwritten accent
```

Не делать все тексты uppercase.

Uppercase — акцент, а не базовый язык интерфейса.

---

# 7. Геометрия

SoyMan избегает привычного SaaS-языка.

Минимум:

* pill-buttons;
* огромных radius;
* floating rounded cards;
* мягких стеклянных blur-панелей.

Основные формы:

* прямоугольник;
* срезанный угол;
* косой край;
* двойная рамка;
* наложенная бумажная полоска;
* локальный разрыв линии.

---

## Радиусы

Базово:

```text
small:  0–2px
medium: 0–3px
large:  0–4px
```

Круглая форма допустима только там, где она функциональна:

* token;
* avatar;
* radio;
* маленький indicator.

---

# 8. Срезанные углы

Один из основных мотивов.

Пример:

```text
╱──────────────┐
│              │
│              │
└────────────╱─┘
```

Важно:

реальный hitbox остаётся нормальным прямоугольником.

Срез — визуальный слой.

---

# 9. Линии

Не идеально стерильные.

Допустимы:

* двойная линия;
* смещённая линия;
* marker overlay;
* маленький разрыв;
* chromatic duplicate.

Но основная structural border остаётся чёткой.

---

# 10. Поверхности

Три основных типа.

## Page

Почти чистая бумага.

Очень лёгкая текстура.

Никаких шумовых паттернов, мешающих тексту.

---

## Panel

Функциональный контейнер.

База:

* paper/surface;
* ink border;
* один декоративный угол или штрих.

Не каждый panel обязан быть уникальным.

---

## Feature Surface

Используется для:

* character card;
* class selection;
* major summary;
* hero section.

Может иметь:

* цветовое пятно;
* иллюстрацию;
* halftone;
* collage;
* крупную display typography.

---

# 11. Character cards в библиотеке

Главная страница может быть гораздо выразительнее листа.

Карточка должна чувствоваться как объект.

Пример композиции:

```text
╱───────────────────────────┐
│ МОРДЕКАЙ               ⋯  │
│ Варвар • уровень 7         │
│                           │
│      [ portrait ]          │
│                           │
│ HP 17 / 28                 │
└───────────────────────╱────┘
   ////// marker stroke
```

Карточки могут различаться цветовым ритмом, но структура остаётся одинаковой.

---

# 12. Character Sheet

Главная установка:

> **Лист не выглядит как сайт.**

Он должен напоминать цифровой игровой лист, поверх которого постепенно появились:

* подчёркивания;
* маркер;
* царапины;
* карточки;
* заметки;
* штампы.

Но плотность информации остаётся высокой.

---

# 13. Mobile Character Sheet

Это главный игровой режим.

Приоритет:

1. HP / core combat;
2. ресурсы;
3. характеристики;
4. tabs;
5. контент.

Декоративность уменьшается рядом с frequently-used controls.

Особенно чистыми остаются:

* HP;
* damage/heal;
* spell slots;
* resources;
* saving throws.

---

# 14. Desktop Character Sheet

Не отдельный дизайн.

Это расширенная версия мобильного языка.

Можно:

* больше воздуха;
* больше decorative framing;
* более крупный портрет;
* дополнительные боковые панели;
* больше видимой информации одновременно.

Но визуальная грамматика та же.

---

# 15. Buttons

## Primary

Характер:

* плотный ink или acid fill;
* чёткая геометрия;
* небольшой cut corner;
* высокий контраст.

Не использовать glow.

---

## Secondary

Paper / transparent.

* ink border;
* слабый marker accent;
* hover через смещение/заливку.

---

## Danger

Всегда визуально явно отличается.

Красный / crimson.

Удаление не должно выглядеть как обычный primary.

---

## Busy

Не перестраивать кнопку.

Меняется:

* текст;
* небольшой indicator.

Размер кнопки стабилен.

---

# 16. Active / Selected

Один из ключевых signature motifs SoyMan.

Не использовать стандартное:

```text
blue border
box-shadow
```

Основной мотив:

**marker stroke / underline / offset paint strip**

Например:

```text
ЗАКЛИНАНИЯ
^^^^^^^^^^^
```

или кислотная неровная полоска за текстом.

Это может стать общим языком для:

* tabs;
* wizard steps;
* selected cards;
* active menu item.

---

# 17. Tabs

Inactive:

* почти чистые;
* ink text;
* слабый border.

Active:

* marker strip;
* bold ink;
* небольшой chromatic offset.

Active tab всегда читается без reliance на цвет alone.

---

# 18. Wizard

Workflow не меняется.

Визуально wizard ощущается как последовательность страниц/глав зина.

Progress:

```text
01 / 12
```

может быть крупной display typography.

Шаги:

* активный шаг — marker highlight;
* завершённые — ink;
* остальные — muted.

Поскольку текущий wizard допускает свободные переходы, дизайн не должен визуально изображать будущие шаги как недоступные.

---

# 19. Modal

Modal — не отдельная «красивая карточка».

Это рабочее overlay-состояние.

Форма:

* paper;
* грубая рамка;
* один cut corner;
* небольшой decoration stroke.

Conflict / Delete могут иметь усиленный visual accent.

---

# 20. Menu

Меню остаётся очень чистым.

Панк-стиль:

* border;
* один offset shadow/stroke;
* highlighted active row.

Не превращать dropdown в иллюстрацию.

---

# 21. Fields

Input / select:

* paper;
* ink border;
* почти без radius;
* сильный focus-state.

Focus:

* acid marker edge;
* outline;
* возможно маленький handwritten tick.

Никакого декоративного шума внутри поля.

---

# 22. Halftone

Используется как структурный эффект.

Хорошо:

* край иллюстрации;
* углы;
* фон карточки;
* большая тень.

Плохо:

* поверх текста;
* поверх всех controls;
* равномерно на весь экран.

---

# 23. Chromatic Aberration

Используется как акцент.

Максимум несколько пикселей.

Хорошо:

* display title;
* выбранная карта;
* illustration edge;
* hover decorative accent.

Плохо:

* body text;
* HP;
* input value.

---

# 24. Datamosh

Редкий special-effect.

Используется:

* wild magic;
* conflict;
* corrupted/magical state;
* hero illustration.

Не является базовым стилем SoyMan.

---

# 25. Marker / Pen

Самый распространённый декоративный эффект.

Можно использовать чаще, чем aberration/datamosh.

Формы:

* underline;
* circle;
* arrow;
* repeated pen stroke;
* strike-through decoration;
* scribble block.

---

# 26. Generated assets

Главное правило:

> Генерируем не готовые интерфейсные блоки, а детали для skin.

Хорошие assets:

* corner;
* divider;
* underline;
* scratch;
* halftone mask;
* paper tear;
* paint stroke;
* sticker;
* decorative frame segment.

Плохой asset:

`panel_650x320_final.png`

---

# 27. Масштабируемость assets

Предпочтительные типы:

* transparent PNG/WebP;
* SVG для простых форм;
* CSS mask;
* repeatable texture;
* 9-slice-compatible frame;
* отдельные corners.

Asset не должен диктовать ширину UI.

---

# 28. Текст в assets

Почти всегда запрещён.

Текст должен быть HTML.

Допустимо только:

* художественная карточка;
* иллюстративный poster element;
* декоративное graffiti без функционального смысла.

---

# 29. Motion

Минимальный.

SoyMan не должен ощущаться как motion-demo.

Разрешено:

* 100–180ms hover;
* лёгкий translate;
* marker reveal;
* небольшой offset;
* modal fade.

Запрещено:

* постоянный glitch;
* floating animation;
* looping datamosh;
* parallax ради parallax.

---

# 30. Home vs Sheet

## Home

Самый выразительный экран.

Разрешено:

* крупная графика;
* большие display-заголовки;
* mascot/illustration;
* асимметрия;
* collage;
* сильные cards.

---

## Sheet

Самый функциональный экран.

Правило:

> Чем чаще элемент нажимают во время игры, тем меньше на нём декоративности.

---

# 31. Empty state

Это одно из мест, где можно сильно показать характер SoyMan.

Например:

* герой/талисман;
* разбросанные листы персонажей;
* кубы;
* маркерные стрелки;
* acid paint.

CTA остаётся абсолютно очевидным:

`Создать персонажа`

---

# 32. Visual noise budget

На одном viewport должен существовать визуальный центр.

Не может одновременно кричать:

* фон;
* header;
* every panel;
* tabs;
* buttons;
* illustration.

Если content card очень яркая — surrounding UI успокаивается.

Если hero state яркий — кнопки проще.

---

# 33. Signature SoyMan motifs

Пять элементов, которые должны постепенно стать узнаваемыми:

1. **marker selection stroke**
2. **cut corners**
3. **yellow + magenta collision**
4. **pen scribbles**
5. **controlled chromatic offset**

Halftone поддерживает систему, но сам по себе не является signature.

Datamosh — seasoning.

---

# 34. Первый эталонный экран: Library

Цель:

> показать весь визуальный характер SoyMan без ограничений боевого UX.

Должны быть проработаны:

* header;
* title;
* character cards;
* create CTA;
* row/menu;
* archive;
* sync status;
* empty state.

Интенсивность:

**7/10**

---

# 35. Второй эталонный экран: Mobile Sheet

Цель:

> доказать, что Fantasy Punk может быть красивым, не мешая играть.

Проработать:

* character header;
* portrait;
* HP;
* key stats;
* tabs;
* section surfaces;
* quick actions.

Интенсивность:

**4/10**

Content artwork внутри:

**8/10**

---

# 36. Красная линия

Никогда не делать:

> обычный современный SaaS UI + грязная текстура поверх.

Fantasy Punk должен быть встроен в:

* геометрию;
* типографику;
* композицию;
* selection language;
* иллюстрации.

Текстура — только последний слой.
