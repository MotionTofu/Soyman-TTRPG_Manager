# Установка OneShot SoyMan на сервер

Пакет содержит собранный визард, чарник и оболочку автономного HTML. На сервере нужны только Docker Engine и Docker Compose v2. Node.js, исходный SoyMan и его база не нужны.

Персонажи сохраняются в браузере посетителя, не на сервере. Ссылка `?character=2` открывает локального персонажа №2 и не является ссылкой для передачи персонажа другому человеку. Для переноса используйте резервную копию или автономный HTML. Аккаунтов, облачной синхронизации и установки полноценного листа как PWA пока нет. Без интернета гарантированным носителем остаётся скачанный HTML; обычная страница ещё не подготовлена к офлайн-перезагрузке.

## 1. Подготовить сервер

Подойдёт Linux-сервер с публичным IP. Установите Docker Engine и Compose plugin по [официальной инструкции для Ubuntu](https://docs.docker.com/engine/install/ubuntu/). Команды ниже выполняются под пользователем, имеющим доступ к Docker; при необходимости используйте `sudo docker`.

Создайте DNS-запись A для своего домена, например `characters.example.com`, указывающую на IP сервера. AAAA добавляйте только при рабочем IPv6. Разрешите входящие TCP 80 и 443 в панели провайдера и файрволе; UDP 443 необязателен. Эти порты должны быть свободны. Если уже установлен Nginx/Caddy, используйте вариант ниже с существующим веб-сервером.

## 2. Загрузить и запустить

Скопируйте полученный `soyman-server-….tar.gz` на сервер через SFTP или `scp`. Создайте каталог и распакуйте архив (подставьте настоящее имя):

```sh
mkdir -p ~/soyman-1shot
tar -xzf soyman-server-….tar.gz -C ~/soyman-1shot
cd ~/soyman-1shot
cp .env.example .env
nano .env
```

В `.env` задайте свой домен **без https:// и без пути**:

```dotenv
DOMAIN=characters.example.com
```

Запустите:

```sh
docker compose config --quiet
docker compose up -d
docker compose logs --tail=100 web
```

Откройте `https://characters.example.com`. Caddy сам получит и будет продлевать сертификат, а HTTP перенаправит на HTTPS. Для выдачи сертификата должны правильно работать DNS и доступ к портам: [документация Caddy](https://caddyserver.com/docs/quick-starts/https).

Сервис автоматически запускается после перезагрузки сервера, если Docker запускается вместе с ОС. Веб-сайт открыт всем, кто знает адрес.

## 3. Проверить после установки

Откройте `/healthz` — должно появиться `ok`. На главной нажмите «Подключить общий справочник», дождитесь загрузки, создайте персонажа. Измените хиты и перезагрузите страницу: изменение должно сохраниться. Скачайте автономный HTML и проверьте его отдельно без сети. Повторите создание в другом браузере: там будет отдельный список персонажей.

Общий справочник входит в пакет только при сборке с `--catalog`. Без него посетители могут импортировать JSON самостоятельно. Публичный справочник доступен для скачивания любому посетителю. Исходная SQLite-база, кампании и персонажи владельца в пакет не включаются. Большие карты могут заметно увеличить размер первоначальной загрузки.

## Обновление и резервные копии

Перед обновлением сохраните предыдущий серверный пакет, `.env` и каталог сайта. Распакуйте новую версию в отдельную папку, перенесите туда прежний `.env`. Из прежней папки выполните `docker compose down` **без `-v`**, из новой — `docker compose up -d`. Фиксированное имя проекта сохраняет тома сертификатов. Для отката остановите новую и запустите старую версию. Не запускайте обе одновременно на одних портах.

Не меняйте домен без переноса персонажей: хранилище браузера привязано к адресу сайта. Очистка данных браузера удаляет локальные листы. Игрокам нужно скачивать резервные копии; резервная копия сервера не содержит их персонажей. Обновление общего справочника применяется после повторного подключения и только к новым персонажам.

Остановка: `docker compose down`. Логи: `docker compose logs --tail=100 web`. Версию образа Caddy можно закрепить в `compose.yaml` по digest после испытания на сервере; поставка использует обновляемый тег `caddy:2-alpine`.

## Если веб-сервер уже есть

Каталог `site/` — обычный статический сайт. Его можно обслуживать существующим Nginx/Caddy по HTTPS на отдельном домене или поддомене. Размещайте в корне домена, не в `/oneshot/`: ссылки ресурсов абсолютные. Разрешите выдачу `.json`, `.html`, шрифтов и изображений, отключите долгий кеш для HTML/JSON. Параметры `?character=…` не требуют серверной маршрутизации. Не публикуйте всю папку репозитория. В этом варианте Compose запускать не нужно.

## Как собрать новый пакет на машине разработчика

Из корня репозитория, после установки зависимостей `client` командой `npm ci --prefix client`:

```sh
cd SoyMan_1shot
node package-server.mjs --catalog private/catalog.json
```

Скрипт проверяет указанный справочник, собирает сайт и автономный лист, создаёт папку и архив в `releases/`. Передайте только архив. Для пакета без общего справочника: `node package-server.mjs`. Локальный `private/catalog.json` можно обновить через `node prepare-catalog.mjs` на машине с базой SoyMan. При сборке не требуется доступ к серверу. Для создания архива нужен `tar` (есть в современных Windows и Linux).
