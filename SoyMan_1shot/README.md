# OneShot SoyMan

Отдельная поставка с настоящими компонентами визарда, повышения уровня и листа D&D 5.5 из SoyMan, общими расчётами и стилями. Цифровые броски отключены.

## Установка на сервер

[Полная инструкция: домен, HTTPS, запуск и обновление](DEPLOY.md). `node package-server.mjs --catalog private/catalog.json --catalog-version 2026.09` создаёт готовый архив в `releases/`: сайт, общий справочник и Docker Compose с Caddy. На сервере исходники и база SoyMan не нужны. Для Vercel — `--vercel` (только статическая папка `site/`, синхронизация скрыта). Без `--catalog` пакет собирается для ручного импорта справочников. Персонажи хранятся в браузере каждого посетителя.

## Запуск

Нужны установленные зависимости соседнего client. Из этой папки:

- npm start — текущий сайт http://localhost:4318/.
- npm run build — сборка в app-dist.
- npm test — проверка типов, затем тесты справочника, экспорта, синхронизации и PWA. Прогонять до коммита при правке данных, экспорта, синхронизации или компонентов листа в client; перед сборкой поставки — обязательно.
- node ../client/node_modules/typescript/bin/tsc -p tsconfig.json — проверка типов.
- npm run test:ui — дымовая проверка в настоящем Chrome при запущенном `npm start`: визард создаёт персонажей (по умолчанию Жрец, Артефактор, Волшебник 5 уровня), затем обходит все вкладки на ПК и телефоне. Падает на ошибках консоли, вылезании за край экрана, кнопках и полях без подписи. Класс и уровень — `UI_CLASSES`, `UI_LEVEL`; путь к браузеру — `CHROME`.

Для локальной разработки node prepare-catalog.mjs читает активную базу SoyMan в режиме read-only и создаёт private/catalog.json. Персонажи и кампании не копируются. npm start сам собирает из него релиз справочника в catalog/ (когда private новее) и отдаёт его по /catalog/*, как это делает сервер: справочник подключается автоматически. private/ и catalog/ исключены из Git.

## Текущий этап

Общий визард и лист, игровые изменения с сохранением в IndexedDB, независимые персонажи и закреплённая версия справочника. Проверка ревизии предотвращает молчаливое затирание правок другого окна. После ошибки запись останавливается; видимый лист можно скачать.

Обычная классовая магия формируется из таблицы развития: визард разделяет заговоры и заклинания доступных кругов. Для волшебника отдельно собираются книга заклинаний и подготовленный из неё список, в том числе при создании сразу на высоком уровне.

Резервная копия JSON содержит персонажа и весь подключённый справочник. Восстановление создаёт нового персонажа. Это промежуточное восстановление, а не финальный экспорт со срезом используемых записей.

Кнопка «Скачать автономный HTML» собирает настоящий React-лист, шрифты, портрет и выбранные записи справочника с общими игровыми правилами в один файл. Сеть запрещена политикой CSP. В автономном листе изменения не сохраняются: в шапке одна кнопка «Внимание» — там объяснено, что персонажа ведут на сайте после импорта файла, и есть запасное «Скачать копию с изменениями»; исходный файл не перезаписывается. Новые предметы и заклинания вводятся вручную, повышение уровня отключено. Поддержаны спутники по чертежам умений и заклинаний: хиты, КЗ, действия, варианты и состояние используют общие компоненты SoyMan. Экспорт спутников из бестиария, отдельных статблоков и внешних изображений пока блокируется с объяснением.

Сайт ставится как PWA: service worker кэширует оболочку, после первой загрузки лист открывается без сети. Вкладки одного браузера узнают о правках друг друга; архив, копия и удаление персонажа есть в библиотеке.

Синхронизация между устройствами и ссылка для просмотра Мастером работают только через сервер основного SoyMan (server/src/routes: sync, shares); статическая поставка такого сервера не содержит. Аккаунтов нет.

Не завершена проверка полноты косвенных зависимостей и классовых исключений. Установка на главный экран и офлайн на реальных iOS/Android ещё не испытаны.
