# Отложено на потом

Задачи, сознательно вынесенные за границы текущей работы. Для каждой —
зачем она нужна, почему отложена и что должно случиться, чтобы к ней
вернуться.

---

## Живые меншены на uid вместо локального id

**Что это.** После работы над переносом модулей формат ссылки в тексте стал
гибридным:

- живая ссылка — `[[being:412|Мирт]]`, локальный id строки;
- подвешенная (цель не установлена) — `[[being@0f3a…|Мирт|Вотердип]]`,
  глобальный uid плюс имя модуля-источника.

Отложенная задача — доделать переход до конца: перевести на uid и живые
ссылки тоже, чтобы локальный id перестал быть «истиной» для ссылок вообще.

**Зачем.** Локальный id верен ровно в пределах одного файла базы. Любой путь
переноса данных обязан отдельно переписывать все id в текстах, и каждый новый
путь, который об этом забудет, снова начнёт молча переклеивать ссылки на
чужие сущности. Особенно это касается будущей синхронизации с сервером, при
требовании оставить мастер-клиент полностью офлайн-редактируемым. При uid в
тексте этот класс ошибок исчезает: переписывать нечего, ключ уже глобальный.

**Почему отложено.** `MentionText` чисто строковый и синхронный: разбирает
токен регуляркой и сразу строит маршрут `DETAIL_ROUTES[type]/id`, без единого
запроса. uid у живых ссылок требует, чтобы рендер умел резолвить uid → id
(или чтобы маршруты принимали uid) — это переработка отображения ссылок во
всём приложении, плюс необратимая миграция всех текстовых полей разом.

**Что уже сделано в эту сторону.** Практически весь фундамент:

- колонка `uid` у всех 13 типов, на которые можно сослаться, с обратной
  засыпкой существующих строк;
- функции разбора и переписывания меншенов в тексте (нужны были для
  экспорта, импорта и слияния);
- подвешенная форма токена — то есть все три разборщика меншенов
  (`MentionText.tsx`, `mentions.ts`, `settings.ts`) уже умеют читать uid из
  текста;
- проход исцеления, умеющий находить uid в базе и переписывать токен.

Остаётся поменять то, что пишется в текст при создании живой ссылки, и
прогнать разовую миграцию `id → uid` по всем текстовым полям.

**Триггер вернуться.** Начало работы над синхронизацией с сервером — либо
первый же случай, когда меншены снова разъехались после переноса.

## Счётчик systems: 5237 при максимальном существующем id 416

**Что это.** В рабочей базе `sqlite_sequence` для `systems` показывает 5237,
хотя самый большой id среди существующих систем — 416, а систем всего 4.
Значит порядка 4800 систем были когда-то созданы и удалены.

**Зачем разбираться.** Само по себе не вредит (id не переиспользуются), но это
не объяснённое поведение: создают системы всего три места в коде, и ни одно не
должно срабатывать тысячи раз. Если там цикл — он всё ещё живой.

**Почему отложено.** На проектирование переноса ссылок не влияет, а раздутый
файл базы лечится независимо — через `VACUUM`.

**Триггер вернуться.** Если счётчик продолжит расти при обычной работе.
