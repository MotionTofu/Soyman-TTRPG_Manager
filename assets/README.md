# Ассеты SoyMan

Единое хранилище рабочих ассетов интерфейса — `assets/library/`.
Единая картотека — `assets/manifest.json`; карточки с превью и поиском
собираются из неё автоматически. Правило зафиксировано в
[ADR-0005](../docs/adr/0005-shared-asset-library.md).

## Посмотреть картотеку

Из корня репозитория:

```sh
npm run assets:serve
```

Открыть `http://127.0.0.1:5188/assets/catalog/index.html`.
Это локальный просмотрщик: он показывает только файлы, перечисленные в
картотеке, и не отдаёт базы кампаний или произвольные файлы репозитория.

Для просмотра без сервера:

```sh
npm run assets:catalog
```

Открыть `assets/catalog/index.html` в браузере. Превью изображений работают
из локальных файлов; загрузка образца шрифта может требовать локального
сервера. `index.json` содержит тот же каталог для инструментов.
Оба результата генерируются и не коммитятся.

## Где что лежит

| Место | Назначение |
|---|---|
| `assets/library/` | Основные рабочие файлы: графика, шрифты, лицензии шрифтов, сопроводительные стили |
| `assets/manifest.json` | Стабильный ID, название, набор, основной файл, пути рабочих копий |
| `client/public/` | Копии для раздачи по прежним URL |
| `client/src/assets/` | Копии для импортов Vite, включая коллекцию логотипов |
| `build/icon.png` | Копия иконки упаковки Electron |
| `SoyMan_1shot/assets/fantasy-punk/` | Исторические исходники, PNG, концепты, атласы, варианты; отдельный раздел картотеки |
| `client/src/rasterAssets.ts` | Реестр ключей значков и текстур для клиентского кода; не второе хранилище файлов |
| `client/src/maps/assets/*-pack.json` | Происхождение и параметры наборов карт; включаются в карточки |

Путь в `source` — основной файл для правок. Каждый путь в `outputs` —
рабочая копия. Несколько идентичных файлов при переносе объединены в
одну запись с несколькими `outputs`. URL и имена импортов сохранены,
регистры существующих имён также сохранены.

Исторические оригиналы в локальных `res/`, `Archive/` и `.scratch/`
не перемещались и не публикуются. Они могут содержать смешанные рабочие
материалы; автоматически считать их все ассетами приложения нельзя.
Сведения из существующих манифестов карт сохранены, без выдумывания
отсутствующих источников и лицензий. Картотека пока не удостоверяет
лицензию каждого изображения.

## Заменить ассет

1. Найти карточку и открыть **основной файл** в `assets/library/`.
2. Заменить его, сохранив назначение и требования соответствующего набора.
3. Выполнить:

```sh
npm run assets:sync
npm run assets:check
npm run assets:catalog
```

Обычные запуски и сборки клиента, OneShot и standalone также выполняют
синхронизацию. Ассеты не подключаются по сети, внешний сервис не нужен.
При изменении основного файла обновляются все его рабочие копии.

## Добавить новый ассет

Можно добавить основной файл и запись в `manifest.json` вручную по
образцу соседней записи. Другой способ — явно принять подготовленный
файл из нужной рабочей папки:

```sh
npm run assets:adopt -- client/public/ui/wizard/new-decoration.webp
npm run assets:sync
```

В записи можно уточнить `title` и `category`. Для значков, вызываемых через
`rasterAsset`, также добавить ключ в `client/src/rasterAssets.ts`; для нового
рабочего ассета Fantasy Punk — роль в CSS и строку в его
`runtime-manifest.json`. Эти реестры описывают способы использования,
а основной файл в любом случае принадлежит общему хранилищу.

`npm run assets:adopt` без пути принимает только новые, ещё не учтённые
файлы из рабочих папок. Существующие основные файлы эта операция
не заменяет. Для принятия намеренной правки существующей рабочей копии
нужен её точный путь. Общий ассет с несколькими копиями изменяется через
основной файл, чтобы одна копия не меняла остальные незаметно.

## Проверки и защита правок

```sh
npm run assets:check
npm run assets:test
```

Общая проверка обнаруживает отсутствующие основные файлы и копии,
незарегистрированные файлы и расхождения байтов. Проверки Fantasy Punk
и растрового реестра дополнительно сохраняют прежние требования к CSS,
формату, весу, именам и оформленным исключениям.

Синхронизация проверяет весь план перед записью. Если рабочая копия
отличается и от последней синхронизированной версии, и от основного
файла, она сохраняется, а операция завершается с ошибкой и путём файла.
Нужно перенести намеренную правку в основной файл или явно принять её
командой `assets:adopt -- <путь>`. Состояние последней синхронизации
хранится локально в игнорируемой `assets/.cache/`.

Исходный хэш `baselineSha256` нужен для первой синхронизации в новом
checkout; актуальные хэши и размеры для просмотра вычисляются из файлов.
Пути в манифесте проверяются, симлинки не допускаются.

В этой миграции рабочие копии остаются в Git для совместимости с
существующими способами запуска. Они проверяются на совпадение с общим
хранилищем. Их удаление из Git — отдельный шаг после перевода всех
нестандартных запусков на синхронизацию.

## Как читать сведения об использовании

Картотека различает прямую ссылку, ключ в реестре, подключение набора,
подключение коллекции логотипов и использование при упаковке. Подключение
набора указывает на файл кода, вычисляющий путь; оно не доказывает,
что каждый его вариант отображается на текущем экране.
«Без найденных ссылок» — кандидаты на проверку человеком, а не список
для автоматического удаления. Превью, размеры, вес и SHA-256 берутся
из реальных файлов; пользовательские изображения кампаний не сканируются.
