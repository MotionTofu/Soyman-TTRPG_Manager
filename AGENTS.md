# SoyMan — TTRPG Manager

Личный менеджер настольных ролевых кампаний. React + TypeScript клиент (`client/`),
Express + better-sqlite3 сервер (`server/`), упаковка в десктоп через `electron/`.
Продуктовый контекст — `PRODUCT.md`, визуальная система — `docs/design-system.md` (v2 «Д»), где что лежит в коде — `DESIGN.md`.

## Порядок работ

1. **Задание.** Обычно это тикет `.scratch/<feature>/issues/NN-*.md` со
   спекой `spec.md` рядом. Решения в спеке уже приняты владельцем — их
   исполнять. Если задание требует нового проектного решения (новая модель
   данных, формат обмена, экран или поведение существующего), а в спеке его
   нет: остановиться и вернуть вопросы — каждый с вариантами и советом,
   какой взять. Решение по умолчанию в код не кладётся.
2. **Ориентация.** Граф кода уже построен в `graphify-out/`; словарь
   предметной области — `CONTEXT.md`, решения — `docs/adr/`.
3. **Перед правкой** — снимок, с которым потом сверяться:
   - `git status`. Незакоммиченные чужие правки — работа параллельной
     сессии: их файлы оставлять как есть, рабочую копию целиком не
     переключать (сравнение «до/после» — через `git show HEAD:<путь>`).
   - Число ошибок `npx oxlint src` в `client`. После работы оно не растёт.
   - Порт 3001. Если слушает — это dev-сервер владельца на его живой базе
     (`tsx watch`): любая правка `server/src` сразу перезапускает его и
     гоняет миграции по `server/data/app.db`. Правку миграций тогда
     вернуть владельцу не применённой, с объяснением.
   - Серверы приложения останавливать только по явной просьбе владельца.
     Во время работы и после завершения проверки или задачи сервер оставлять
     запущенным: окончание ответа в чате не является просьбой его выключить.
     Работающий стенд и его каталог не удалять. Это правило имеет приоритет
     над шагом «Убрать» в `docs/agents/app-stand.md`.
4. **Правка.** Ловушки, которые не видны из кода:
   - Миграция — новым шагом в **конец** `migrateDatabase`
     (`server/src/db/db.ts`); колонка в `CREATE TABLE` `schema.sql` — с
     парным `ALTER`. У друга владельца база старого релиза, шаги она
     проходит по порядку файла.
   - Сервер берёт `@soyman/shared` из собранного `shared/dist`, клиент —
     из исходников. После правки `shared/src` — `npm run build` в
     `shared`, иначе сервер молча выбросит новые поля.
   - Ассеты `/ui/fantasy-punk/` ссылаются только из
     `client/src/fantasy-punk-skin.css` (переменная `--skin-*`, в других
     CSS — `var(--skin-*)`); картинки листа D&D — фоном через CSS, не
     `<img>`: автономный лист OneShot встраивает только CSS `url()`.
   - POST-эндпоинт, который на деле читает, вызывается с
     `{ broadcast: false }` (`client/src/api/client.ts` считает любой
     не-GET записью и сбрасывает весь кэш).
   - Концы строк — как в самом файле; новые файлы — LF.
5. **Проверка** — по таблице ниже, по каждой задетой области.
6. **Отчёт.** Что сделано; каждая проверка — командой и результатом;
   что не проверено и почему. Дефект, найденный попутно и не
   починенный, записывается в тему `Backlog/` (место в коде, причина,
   почему не тронут) — ответ в чате исчезнет, файл останется.
   Коммит — только если задание его просит, и только своими ханками:
   файл с чужими правками добавляется через `git diff` → свои ханки →
   `git apply --cached`. Сообщение — по-русски, в стиле `git log`.

Сборки релиза (`npm run dist*`) и выкладку наружу ведёт владелец.

## Проверка после задания

Код возврата смотреть без пайпа (`cmd | head` возвращает код `head`).
Тесты гонять целиком, падение «не моего» теста — тоже в отчёт.

| Задето | Команды (из папки) |
|---|---|
| `client/src` | `client`: `npm run lint` (oxlint + проверки дизайна), `npx tsc -p tsconfig.app.json --noEmit`, `npm test` |
| `server/src` | `server`: `npx tsc --noEmit`, `npm test` (в нём и миграции старых баз) |
| `shared/src` | `shared`: `npm run build`, `npm test`; затем строки `server` и `client` |
| лист D&D (`client/src/components/dnd`, стили листа) | `SoyMan_1shot`: `npm test` — не `node --test`: `pretest` пересобирает автономный HTML |
| ассеты, skin | корень: `npm run assets:sync`, `npm run assets:check` |
| тексты для людей | сверка с оригиналом по смыслу, концы строк |

`npx tsc --noEmit` в `client` не проверяет ничего (`"files": []`) — только
`-p tsconfig.app.json`.

Правка видна в приложении — проверить и там, со стороны Мастера, на стенде
с копией базы: [`docs/agents/app-stand.md`](docs/agents/app-stand.md).
Без браузера — так и написать в отчёте: «в приложении не проверено».

## Ассеты приложения

Основные рабочие файлы графики и шрифтов — в `assets/library/`, учёт —
в `assets/manifest.json`. Пути в `client/public/`, `client/src/assets/`
и `build/icon.png` являются синхронизируемыми копиями. Перед добавлением
или заменой ассетов прочитать `assets/README.md`; после правок выполнить
`npm run assets:sync` и `npm run assets:check`. Исторический архив
Fantasy Punk хранит концепты и варианты; рабочие файлы правятся в
общем хранилище. Не перезаписывать чужие правки рабочих копий.

## Agent skills

### Issue tracker

Локальный markdown: спеки и тикеты лежат файлами в `.scratch/<feature-slug>/`. См. `docs/agents/issue-tracker.md`.

### Triage labels

Канонические лейблы без переименования (`needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`). См. `docs/agents/triage-labels.md`.

### Domain docs

Single-context: `CONTEXT.md` + `docs/adr/` в корне репозитория. См. `docs/agents/domain.md`.
