# @soyman/shared

Правила и типы, общие для клиента и сервера.

Пакет заведён 2026-09-10, когда выяснилось, что бонус мастерства считается
четырьмя способами, макс. хиты — тремя, а `normalizeDndCharacter` заперт внутри
React-файла на 11 751 строку, из-за чего **семь серверных мест** разбирают
сохранённый лист персонажа мимо него. До этого общего модуля в проекте не было,
и это было записано прямо в коде: `skillCatalog.ts` — «Общего разделяемого
модуля между `client/` и `server/` в проекте нет, поэтому списка два; правки
вносить в оба».

## Как подключён

- **Сервер** зависит через `file:../shared` и импортирует собранный `dist`.
  Поэтому `npm run build` сервера собирает сначала этот пакет.
- **Клиент** берёт исходники из `src` алиасом Vite `@shared` — сборка ему не
  нужна, Vite бандлит TypeScript сам.

Такая форма выбрана осознанно: она не трогает ни путь запуска сервера
(`dist/index.js`), ни `electron/main.js`, ни топологию `node_modules`, на
которой висит `electron-rebuild` для `better-sqlite3`. Поломка любого из этих
трёх мест видна только на собранном установщике.

## Правила пакета

1. **Никакого React и никакого DOM.** `tsconfig` здесь без `lib: DOM` — импорт
   `.tsx` сюда не скомпилируется. Это не строгость ради строгости: пакет
   исполняется и на сервере.
2. **Никакой сети.** Всё, что требует похода в компендиум, готовится снаружи и
   приходит внутрь данными.
3. **Чистые функции.** Вход — сохранённый лист, выход — числа. Это и делает
   interface тестовой поверхностью.
