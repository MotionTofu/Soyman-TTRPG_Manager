# Формат импорта систем — `system-import/1`

Промежуточный формат между произвольным текстом (книга правил, PDF, вики) и компендиумом
SoyMan. Нейросеть читает исходник и выдаёт JSON по этой спецификации; приложение проверяет
его валидатором, показывает экран сверки и создаёт или **обновляет** записи.

Это второй формат рядом с [`adventure-import/1`](../adventure-import/format.md). Общий у них
весь конвейер — ключи, ссылки, меншены, деление ошибок и предупреждений, экран сверки,
транзакция и откат. Разные — типы сущностей: там локации и сцены, здесь классы и заклинания.

## Главное отличие от импорта приключений: повторный импорт обновляет

Приключение заливается один раз. Книга правил — источник, к которому возвращаются: нашли
опечатку, вышло исправление, дозаполнили раздел. Поэтому **ключ здесь долговечен**: импорт
запоминает, какая запись создана под каким ключом, и повторный импорт того же ключа правит
ту же запись, а не плодит вторую.

Что это значит на практике:

- ключи должны быть **стабильны между версиями файла**: `spell.fireball` сегодня и через
  полгода — одно и то же заклинание;
- переименование в книге ключ не меняет: меняется только `name`;
- если запись правили руками в приложении, экран сверки покажет, что именно перезапишется,
  и позволит снять галочку.

## Правила, общие для всего файла

**Ключи.** У каждой сущности обязателен `key` — латиницей, в нижнем регистре, с префиксом
типа: `mech.`, `spell.`, `class.`, `sub.`, `feat.`, `feature.`, `species.`, `bg.`, `eq.`,
`item.`, `mon.`. Например `spell.fireball`, `class.wizard`, `sub.evocation`,
`mech.damage.fire`. Ключ уникален в пределах файла и стабилен между файлами.

**Ссылки.** Везде, где нужно сослаться на другую сущность, пишется её `key`.

Ссылка может указывать на запись, которой в файле нет: глава заклинаний ссылается на классы,
а те либо приехали прошлым импортом, либо заведены в компендиуме руками и ключа не имеют.
Второе — обычное дело при первом импорте в непустую систему, поэтому это не ошибка: экран
импорта показывает такие ссылки отдельным списком и предлагает связать их с существующими
записями. Связь запоминается навсегда, так что связывать приходится один раз. Точное
совпадение английского оригинала в скобках (`class.wizard` → «Волшебник [Wizard]») экран
подставляет сам, остальное — выбором из списка, где подходящее поднято наверх.

Несвязанная ссылка импорт не останавливает: запись приедет без неё, а в предупреждениях
будет сказано, что именно не записалось.

**Меншены в тексте.** Внутри любого текстового поля: `[[spell.fireball|Огненного шара]]`,
где после `|` — форма слова в нужном падеже.

**Разметка.** В текстовых полях `**жирный**`, `*курсив*`, строки-заголовки `## Заголовок`,
списки строками `- пункт`, таблицы в markdown.

**Незаполненное не пишем.** Всё, кроме `format`, `system` и ключей, необязательно. Модель,
которая не нашла поле в источнике, должна его пропустить, а не выдумывать.

## Каркас файла

```json
{
  "format": "system-import/1",
  "language": "ru",
  "system": {
    "key": "dnd55",
    "name": "D&D 5.5",
    "description": "…"
  },
  "source": { "title": "Player's Handbook 2024", "part": "Глава 3. Классы" },
  "mechanics": [], "spells": [], "classes": [], "species": [],
  "backgrounds": [], "feats": [], "equipment": [], "magic_items": [], "monsters": []
}
```

`source` ни на что не влияет механически и нужен человеку на экране сверки: по нему видно,
какой кусок книги приехал.

## Волны

Формат описывает все разделы сразу, но поддержка включается по частям — в порядке
зависимостей. Ссылаться можно только на то, что уже поддержано или объявлено в этом же файле.

1. **Справочник** (`mechanics`) — типы урона, состояния, школы магии, языки, владения.
   Корень зависимостей: на него ссылаются все остальные.
2. **Заклинания** (`spells`).
3. **Снаряжение и магические предметы** (`equipment`, `magic_items`).
4. **Классы, виды, предыстории, черты** (`classes`, `species`, `backgrounds`, `feats`).
5. **Бестиарий** (`monsters`).

---

## `mechanics` — справочник

Плоский список позиций, разложенный по именованным группам. Группы — те же, что заводит
приложение: «Типы урона», «Состояния», «Школы магии», «Языки», «Владения оружием»,
«Владения доспехами», «Владения инструментами», «Особое восприятие», «Скорости
передвижения», «Типы существ и их особенности», «Свойства оружия», «Мастерство оружия»,
«Мировоззрение».

```json
{ "key": "mech.damage.fire", "group": "Типы урона", "name": "Огненный", "description": "…" }
```

## `spells` — заклинания

```json
{
  "key": "spell.fireball",
  "name": "Огненный шар [Fireball]",
  "level": 3,
  "school": "mech.school.evocation",
  "casting_timing": "Действие",
  "casting_timing_other": "",
  "range": "150 футов",
  "duration": "Мгновенная",
  "ritual": false,
  "concentration": false,
  "components": { "v": true, "s": true, "m": "крошечный шарик из гуано и серы" },
  "classes": [{ "ref": "class.wizard" }, { "ref": "sub.light", "grant_level": 3 }],
  "checks": [{ "id": "save1", "type": "save", "save_ability": "Ловкость" }],
  "effects": [
    {
      "type": "damage",
      "when": "save_fail",
      "check": "save1",
      "dice": "8к6",
      "damage_type": "mech.damage.fire",
      "half_on_success": true,
      "upcast_per_level": "1к6"
    }
  ],
  "description": "…"
}
```

**`casting_timing`** — одно из `Действие`, `Бонусное действие`, `Реакция`, `Иное`. Для
реакции в `casting_timing_other` пишется условие срабатывания целиком («когда вас поражают
броском атаки»); для «Иное» — сколько времени («10 минут»).

**`classes`** — кому доступно. Ссылка на класс значит «есть в списке заклинаний класса».
Здесь же можно сослаться на **вид** (`species.`) — книга пишет «этот заговор знает лесной
эльф» в том же списке. В компендиуме это хранится с другой стороны, у вида, в «обретаемых
заклинаниях»; импорт разворачивает ссылку сам, уровень по умолчанию первый.
Ссылка на **подкласс** с `grant_level` значит «подкласс получает это заклинание всегда
подготовленным с такого-то уровня» — в 5.5 это одно и то же, и отдельно список
«обретаемых заклинаний» у подкласса заполнять не нужно.

**`checks`** — броски, которыми заклинание разрешается: `type` = `attack` или `save`.
У атаки `attack_range` = `melee` | `ranged`; у спасброска `save_ability` — русское название
характеристики. `id` локален внутри одного заклинания, эффекты ссылаются на него.
Бросков может быть несколько: у Ледяного ножа это дальняя атака и спасбросок Ловкости.

**`effects`** — что происходит. `when` = `always` | `hit` | `miss` | `save_fail` |
`save_success`; при всех значениях, кроме `always`, обязателен `check`. Типы:

| `type` | поля |
|---|---|
| `damage` | `dice`, `damage_type` (ссылка), `half_on_success`, `upcast_per_level`, `cantrip_scaling` |
| `heal`, `temp_hp` | `dice`, `upcast_per_level` |
| `condition`, `condition_remove` | `condition` (ссылка на `mech.`) |
| `movement` | `movement_kind` = `push`\|`pull`\|`teleport`\|`speed`, `distance` |
| `zone` | `zone_shape`, `zone_size` |
| `roll_modifier` | `modifier` |
| `summon`, `transform`, `create_object`, `defense`, `special` | `text` |

`upcast_per_level` — прибавка за круг ячейки выше собственного; `cantrip_scaling` —
прибавка заговора на 5/11/17 уровнях персонажа. Это разные механики, путать нельзя.
Если тип урона выбирается при накладывании, вместо ссылки пишется `"damage_type": "choice"`.

**`cost`** — чем оплачивается: `{ "kind": "spell_slot" }`, `{ "kind": "resource", "amount": 1 }`,
`{ "kind": "uses", "amount": 2, "per": "long_rest" }`, `{ "kind": "hit_dice" }`. У заклинаний
почти всегда `spell_slot` и можно не писать.

## `classes` — классы

```json
{
  "key": "class.wizard",
  "name": "Волшебник [Wizard]",
  "short_description": "Исследователь и практик тайной магии",
  "hit_die": "к6",
  "primary_abilities": ["Интеллект"],
  "spellcasting_ability": "Интеллект",
  "saving_throws": ["Интеллект", "Мудрость"],
  "subclass_level": 3,
  "weapon_profs": ["mech.weapon.simple"],
  "armor_profs": [],
  "tool_profs": [],
  "skill_choice_count": 2,
  "skill_choice_options": ["История", "Тайная магия"],
  "starting_equipment": {
    "a": { "items": [{ "ref": "eq.dagger", "qty": 2 }], "gold": "5", "text": "2 Кинжала, … и 5 ЗМ" },
    "b": { "gold": "55" }
  },
  "progression": {
    "columns": [
      { "label": "Уровень", "role": "level" },
      { "label": "Бонус владения", "role": "prof_bonus" },
      { "label": "Классовые умения", "role": "features" },
      { "label": "Заговоры", "role": "cantrips" },
      { "label": "Ячейки 1", "role": "slot1" }
    ],
    "rows": [["01", "+2", "Сотворение заклинаний", "3", "2"]]
  },
  "features": [
    { "key": "feature.wizard.ritual", "name": "Знаток ритуалов", "level": 1, "description": "…" }
  ],
  "options": { "title": "Таинственные воззвания", "entries": [] },
  "description": "…"
}
```

**`progression`** — таблица развития **структурой**, а не markdown-текстом. Именно из неё
приложение считает ячейки заклинаний и пулы ресурсов, поэтому текстовую таблицу вместо неё
слать бессмысленно. `rows` — массив массивов, порядок значений соответствует `columns`.

Роль колонки (`role`) говорит, что приложение умеет по ней считать:

| `role` | смысл |
|---|---|
| `level` | уровень класса |
| `prof_bonus` | бонус владения |
| `features` | умения, полученные на уровне |
| `cantrips`, `prepared` | число заговоров и подготовленных заклинаний |
| `slot1`…`slot9` | ячейки соответствующего круга |
| `slots_packed` | все ячейки одной строкой: `1-4, 2-3` |
| `pact_slots`, `pact_level` | Договор магии: число ячеек и их круг |
| `resource` | расходуемый пул (Ярость, Очки чародейства) |
| `stat` | показатель по уровню, тратить нечего (Урон ярости, Кость вдохновения) |
| *(пусто)* | колонка показывается, но ничего не значит |

Разница между `resource` и `stat` — есть ли что тратить. `Ярость 3` — расходуемый пул,
`Урон ярости +2` — показатель. Числовой вид не решает: «Известные схемы 4» — тоже показатель.

**`features`** — умения класса, вложенным списком. Каждое со своим ключом, чтобы на него
можно было сослаться и чтобы повторный импорт нашёл его снова. У умения, которое
применяется действием, ставится `casting_timing` и, если есть, `checks`/`effects`/`cost` —
поля те же, что у заклинания. Без `casting_timing` умение считается пассивным и во вкладку
«Действия» листа не попадает.

**`subclasses`** — отдельным полем, каждый со своим `features`. Заклинания подкласса
объявлять здесь не нужно: они выражаются ссылкой из самого заклинания (см. `spells.classes`).

## `species` — виды

```json
{
  "key": "species.elf",
  "name": "Эльф [Elf]",
  "size": "Средний",
  "size_choice": true,
  "creature_type": "mech.type.humanoid",
  "senses": [{ "ref": "mech.sense.darkvision", "distance": "60" }],
  "speeds": [{ "ref": "mech.speed.walk", "distance": "30" }],
  "granted_spells": [{ "ref": "spell.light", "grant_level": 1 }],
  "features": [],
  "description": "…"
}
```

`size` — одно из `Крошечный`, `Маленький`, `Средний`, `Большой`, `Огромный`, `Громадный`.
`size_choice: true` — вид позволяет выбрать между этим размером и меньшим (в 5.5 так у
большинства). Прозу про рост в футах — в `description`, не в `size`.

Языки виду не приписываются: в 5.5 они выбираются независимо.

## `equipment`, `magic_items` — снаряжение

```json
{
  "key": "eq.dagger",
  "name": "Кинжал",
  "category": "Оружие",
  "cost": "2 ЗМ",
  "weight": "1 фунт",
  "damage": "1к4 колющий",
  "properties": ["mech.wprop.finesse"],
  "mastery": "mech.wmastery.nick",
  "attack_melee": true,
  "attack_ranged": true,
  "description": "…"
}
```

`category` для `equipment` — `Оружие`, `Доспехи`, `Наборы снаряжения`, `Фокусировка`,
`Инструменты`, `Ремесленные инструменты`, `Прочие предметы`. У доспехов вместо `damage`
идут `armor_type`, `ac`, `dex_bonus` (прибавляется ли модификатор Ловкости),
`max_dex_bonus`, `str_requirement`, `stealth_disadvantage`. У инструментов — `ability`
и `usage`.

У магических предметов — `item_type`, `rarity`, `attunement`, `classes` и `price`.
Цена названа `price`, а не `cost`, потому что `cost` у всего применимого уже занят
под «чем оплачивается применение» (ячейка, ресурс, использования).

**Наборы** (`Наборы снаряжения`) перечисляют содержимое ссылками в `contents`:
`[{ "ref": "eq.rope", "qty": 1 }]`. Импорт это сохраняет, но экран пока не показывает
и «взять набор» содержимое не разворачивает — присылать всё равно стоит, книга под
рукой сейчас, а поле для неё уже есть.

## `backgrounds`, `feats`, `monsters`

`backgrounds` — `abilities`, `origin_feat` (ссылка), `skills`, `tools`,
`starting_equipment` (та же форма, что у класса), `description`.

`feats` — `category` (`Черта происхождения`, `Универсальная Черта`, `Тёмный Дар`,
`Боевой Стиль`, `Эпический дар`), `prerequisite`, `description`, плюс
`casting_timing`/`checks`/`effects`, если черта что-то делает активно.

`monsters` — статблок той же формы, что в `adventure-import/1` (см. его спецификацию,
раздел «Статблок»), плюс ключ и описание.

## Ошибки и предупреждения

**Ошибка** — импорт невозможен: сломан JSON, чужой `format`, дубль ключа, ссылка в никуда,
`role` вне списка, `when` без `check`, уровень заклинания вне 0–9.

**Предупреждение** — импорт пройдёт, но что-то потеряется: меншен на несозданную сущность
останется текстом; у заклинания есть `damage` без `damage_type`; у класса есть
`progression`, но нет колонки с ролью `level`; строк в таблице развития не 20.

Ронять разбор целой книги из-за одной кривой строки нельзя — на пробных прогонах такие
строки есть в каждом файле.

## Что происходит при импорте

`POST /api/system-import/validate` — разбирает файл и ничего не пишет. Отвечает
списком ошибок и предупреждений, счётчиками по разделам, списком подходящих систем
(по ключу прошлых импортов и по названию) и главной цифрой: сколько записей файл
**перепишет**, а сколько заведёт заново.

`POST /api/system-import/apply` — пишет одной транзакцией: либо вся глава, либо ничего.

Порядок записи внутри — два прохода. Первый заводит все записи и раздаёт им id,
второй заполняет содержимое, когда ссылаться уже есть на что. Поэтому в файле не
нужно следить за порядком: заклинание может ссылаться на класс, который описан ниже.

Правка бережная: в записи переписываются только те поля, которые файл действительно
прислал. Дописанное руками в редакторе остаётся — импорт не считает себя единственным
автором записи.

`DELETE /api/system-import/batches/:id` — откат: созданное удаляется, переписанное
возвращается к прежнему виду (прежнее содержимое хранится вместе с батчем). Связь
«ключ → запись» при этом сохраняется у чужих записей и уходит вместе с созданными.

`GET /api/system-import/keys?system_id=…` — ключи, уже занятые в системе. Их надо
вкладывать в промпт следующей главы, чтобы модель ссылалась на приехавшее, а не
выдумывала для того же типа урона второй ключ.
