# Как сделать рабочую тетрадь для SoyMan

Шаблон тетради — обычный Markdown, такой же, каким пишутся рабочие тетради курсов. SoyMan сам находит в нём графы. Готовый пример — `workbook-example.md` в «Тетради и шаблоны».

1. Напишите тетрадь в Markdown (или возьмите тетрадь курса как есть) и сохраните в UTF-8.
2. В «Тетради и шаблоны» нажмите «Загрузить шаблон» и выберите файл `.md`.
3. Создайте тетрадь по шаблону и дайте ей название; при желании укажите кампанию, сеттинг или приключение.
4. В книге нажмите «Рабочая тетрадь», выберите шаблон, свою тетрадь и лист.

## Что становится графой

| В Markdown | В тетради |
| --- | --- |
| Первый `# Заголовок` | Название тетради |
| Остальные `# Заголовок` | Листы (закладки 01…N) |
| Текст сразу под `#` листа | Свёрнутый блок «О листе» |
| `## Раздел`, `### Подраздел` | Заголовки внутри листа |
| `**Метка:** _[заполнить]_` или `**Метка:**` и одна линия `____` | Строка |
| Метка и несколько линий `____` или пустые `1. ____` | Текст |
| `**Запись:** _[заполнить]_` под `## Разделом` | Текст с названием раздела |
| `*Курсив*` и прочий текст перед графой | Подсказка к графе |
| `- [ ] пункт` или `□ пункт` | Чек-лист |
| Чек-лист под `## ГОТОВНОСТЬ` или `## Самопроверка` | Готовность: по ней считается прогресс листа |
| Таблица с пустыми клетками, до 4 колонок | Таблица; пустых строк в образце — столько строк сразу |
| Такая же таблица шире 4 колонок | Повторяемые карточки: строка — карточка с подписанными полями |
| Таблица с заполненной первой колонкой | Таблица с заданными строками |
| Колонка `Тип: друг / враг / неясно` | Выбор из вариантов |
| Таблица `**МЕТКА**<br>_[заполнить]_` | Каждая клетка — своя графа |
| Блок ```` ```text ```` с `Метка:`, `[ ] вариант`, `- подпункт:` | Форма: строки, отметки, подпункты |
| Таблица, где все клетки заполнены | Справка, без ответов |

Варианты выбора короткие, через `/`. Длинное «что находят / как найти / ведёт к тайне» остаётся подсказкой формата, а не выбором.

## Невидимые пометки

То, чего нет в обычной разметке, пишется HTML-комментарием — при чтении Markdown его не видно.

- `<!-- шаблон: travel-journal; версия: 2 -->` в начале файла — ключ и номер версии. Без них ключ берётся от шаблона с тем же названием (или из названия), а версия растёт сама, когда текст изменился.
- `<!-- карточка -->` перед `## Разделом` — весь раздел становится повторяемой карточкой. `<!-- карточка: существо -->` — карточка будущей сущности.
- `<!-- поле: force.want -->` перед графой — её значение относится к полю модели (например, «Хочет» у двигателя силы).
- `<!-- тип: страница -->` перед графой — большая страница для свободного текста; `<!-- тип: картинка -->` — картинка.
- `{#key}` в конце заголовка или метки — постоянный ключ, если название будет меняться.

## Версии и сохранность

Ответы привязаны к ключам граф. Без `{#key}` ключ — транслит первого названия, поэтому переименованная графа считается новой.

Загруженный изменённый файл становится новой версией; тетради остаются на своей, пока Мастер не обновит их в «Версии шаблона». При обновлении ответы переносятся в графы с тем же названием, остальное можно сопоставить вручную. Ответ, которому не нашлось графы, не пропадает: он виден на листе в свёрнутых «Прежних графах» и выгружается в экспорт.

## Ограничения

До 200 листов, до 200 граф на листе, до 4000 во всём шаблоне; до 500 строк или карточек в одном ответе; файл шаблона — до 1 МБ. Графы не запускают код.
