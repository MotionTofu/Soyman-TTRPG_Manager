# 10 — Катсцены

Мастерская аудиовизуальных катсцен и их показ на втором экране.

Базовая версия описана в [спецификации](../.scratch/cutscenes/spec.md)
по grilling 2026-10-25, Q1–Q73; ТЗ подтверждено владельцем.
Реализация разбита на [16 тикетов](../.scratch/cutscenes/plan.md).

## Идеи на будущее

### КС1 — Гибрид ручных блоков и событий по времени
**Вид:** идея · **П3**
Развить ручную последовательность шагов до гибридного воспроизведения:
пробел запускает следующий блок, а внутри блока изображение и звук могут
меняться автоматически в заданные моменты. Например: ведущий запускает
видение, через 10 секунд меняется картинка, через 25 — начинается другой трек;
следующий блок по-прежнему запускается вручную.
**Где.** Будущие мастерская и проигрыватель катсцен; существующие точки
интеграции — `client/src/components/presentation/` и `client/src/sound/`.
**Откуда.** Grilling катсцен 2026-10-25, Q1: для первой версии владелец
выбрал ручные шаги (А), гибрид (В) прямо попросил записать в бэклог.
**Почему отложено.** Для первой версии выбран ручной темп. Временные события
внутри блока требуют отдельного проектирования.
**До реализации решить.** Поведение таймеров при паузе, ручном переходе,
возврате и пропуске блока; связь событий с телесуфлёром; устройство редактора
и совместимость с катсценами из ручных шагов.
**Готово, когда.** Отдельным grilling согласованы правила и спецификация;
в показе события внутри блока выполняются по времени, а переход между
блоками остаётся ручным, с изоляцией пробела от других действий приложения.

## Попутные дефекты

### КС2 — Общая галерея отклоняет AVIF из-за имени контейнера Sharp
**Вид:** баг · **П2**
В `server/src/routes/gallery.ts` список `ALLOWED_SHARP_FORMATS` содержит
`avif`, а проверка после `sharp(buf).metadata()` сравнивает именно `format`.
Sharp возвращает для настоящего AVIF `format: "heif", compression: "av1"`;
поэтому файл проходит фильтр MIME/расширения, но отклоняется проверкой байтов.
**Откуда.** Найдено при реализации катсцен 03, 2026-10-25. Проверено локальной
генерацией AVIF через Sharp и чтением metadata. В импорте самих катсцен
этот случай уже учтён; речь о существующем общем маршруте галереи.
**Почему не исправлено здесь.** Тикет 03 отвечает за независимые материалы
катсцен. Общая галерея обслуживает несколько разделов, её правка и регресс
выделены отдельно, чтобы не расширять границы задачи.
**Готово, когда.** Настоящий AVIF импортируется в общую галерею и читается
после повторного запроса; контейнер HEIF с неподдерживаемым кодеком не
принимается как AVIF. Есть проверка реальных байтов, а не только MIME.

Дополнение при реализации 04: такая же проверка `format` стоит в
`server/src/story/presentation.ts`, `processPresentationImage` — общий импорт
фона/слоёв сцен и обложек. Sharp AVIF здесь также возвращает `heif` + `av1`,
которых allow-list не принимает. В 04 менялся вывод уже сохранённых кадров,
импорт представлений не тронут. При исправлении КС2 охватить и этот путь.

### КС3 — Несколько главных окон могут создавать несколько обычных звуковых движков
**Вид:** дефект для проверки · **П2**
`client/src/main.tsx` монтирует AudioPlayerProvider для каждого обычного
окна; `client/src/layout/AppShell.tsx` — SoundEngineProvider. Каждый движок
подписывается на одни команды `client/src/sound/bus.ts`; выбора единственного
главного звукового окна в этих местах нет. При двух полных окнах приложения
одна команда вынесенного пульта может запускать два источника, а снимок
одного движка не представляет фактическое звучание второго.
**Откуда.** Вывод по коду при реализации катсцен 05, 2026-10-25. Слышимая
проба с двумя обычными главными окнами не проводилась; вынесенный пульт
без AppShell и беззвучное окно игроков сами этого случая не создают.
**Почему не исправлено здесь.** 05 вводит снимок и захват каналов текущего
движка. Выбор главного окна для всего обычного аудио требует отдельного
решения о передаче управления и восстановлении уже работающего плеера.
Серверный владелец запуска 07 защищает катсцену, но сам по себе не выбирает
хост всех обычных плееров приложения.
**Готово, когда.** Проверен сценарий двух полных окон; обычный звук играет
из одного хоста, команды и состояние пульта согласованы. Закрытие/reload
хоста и запуск катсцены не оставляют параллельных источников.

### КС4 — Дедупликация может повторно выдать изменённый файл по прежнему хешу
**Вид:** баг · **П2**
**Где.** server/src/services/vaultDedup.ts, storeDeduped/storeDedupedFile:
кандидат по сохранённому хешу повторно используется после проверки существования
пути, без сверки текущего содержимого. Если байты по этому пути изменены вне
этого механизма, индекс продолжает сопоставлять прежний хеш уже другим байтам.
Последующий импорт прежнего содержимого может получить неверный файл.
**Откуда.** Полный серверный checkpoint катсцен 07, 2026-10-26:
mutable-фикстура была зарегистрирована в dedup, затем перезаписана для
проверки независимости катсцены. Это влияло на последующие импорты фикстур.
Собственный помощник server/src/test/cutsceneFiles.ts исправлен: изменяемые
исходники пишутся напрямую, не объявляя их неизменяемыми dedup-объектами.
Весь серверный набор после этого повторён; проверки медиа катсцен проходят.
**Почему не исправлено здесь.** Общий storage/dedup обслуживает все разделы
и содержит чужие незакоммиченные изменения. Его политика внешних изменений
и инвалидирования индекса выходит за рамки сохранённого запуска 07.
**Готово, когда.** После изменения/подмены файла старый hash-кандидат не
используется для других байтов; проверка/инвалидация и обновление индекса
покрыты тестами повторного импорта и не разрушают существующие ссылки.
