# 09 — Ваншот

`SoyMan_1shot/` — автономный визард и чарник D&D для ваншотов (PWA,
автономный HTML, каталог справочника). Первая игра — 2026-09-27. Сверено
2026-10-22; код ваншота с 2026-10-07 не менялся.

Источники: `A/SoyMan_1shot/REVISION.md` «Находки», `A/SoyMan_1shot/Rework/In_Audit.md`
§20, `In_Audit_2.md` §10; тикеты `A/.scratch/oneshot-soyman/`,
`A/.scratch/oneshot-visual-redesign/` (через `_входящие`).

Пределы модели листа, общие с основным чарником, — в «Лист и системы», Д29;
красный тест `lssGear` — С20.

## Долги

### О1 — `main.tsx` знает всё сразу
**Вид:** долг · **П3**
Загрузка, очередь, бэкап, восстановление, экспорт, аудит и каталог — в
одном файле, слоя сценариев нет, тестировать нечего. Аудит видел 169 строк,
сейчас 1655.
**Где.** `SoyMan_1shot/app/main.tsx`.
**Проверено 2026-10-22.** Размер файла.
**Откуда.** `A/SoyMan_1shot/Rework/In_Audit.md` §20, п. 2.

### О2 — Неявная зависимость от `client/`
**Вид:** долг · **П3**
Ваншот берёт из основного клиента пропсы трёх компонентов, `DndRuntimeContext`,
~10 маршрутов, формат статблока, формы `dndCompendium`, ключ
`dnd-wizard-draft:*` и версии пакетов из `client/node_modules`. Ломается
молча. Тот же вопрос — тикет «общие границы чарника и контракт пакета».
**Откуда.** `In_Audit.md` §20, п. 1; `A/.scratch/oneshot-soyman/issues/03-shared-boundaries.md`.
**Готово, когда.** Карта зависимостей и контракт записаны; проверка паритета ловит расхождение.

### О3 — Каталог, черновик и бэкап без страховки
**Вид:** долг · **П3**
Не перепроверялось 2026-10-22 (удаление каталога с тех пор появилось —
`app/repository.ts`, `catalog-manager.mjs`):
- потерянный каталог — деградация: нет проверки «у всех персонажей есть
  каталог» и починки;
- черновик визарда в `localStorage` делит пространство имён с основным
  SoyMan; переполнение квоты не обрабатывается;
- бэкап тащит весь каталог (аватары base64 дважды), лимит чтения 256 МБ при
  каталоге ~130 МБ;
- автономный HTML держится на маркере `__ONESHOT_PAYLOAD__` и `#oneshot-payload`;
- два «сайта» (lab и основной) делят имя, README их смешивает;
- ошибка сохранения — только красный баннер, без журнала и проверки IndexedDB.
**Откуда.** `In_Audit.md` §20, пп. 3–9.

## Решения

### О10 — Вес каталога: убрать оригиналы картинок
**Вид:** решение · **П3**
Замер: оригиналы (`large`) — 84 % веса; без них каталог — 19,9 MiB сырого,
~11 MiB по проводу; ядро правил отдельно — 5,1 MiB / 0,55 MiB. Одно удаление
поля решает 86 % проблемы без новых форматов; разделять правила и медиа —
только если 11 MiB всё ещё много. Решать владельцу. Оригиналы пока в
каталоге (`prepare-catalog.mjs:37`, `avatar_large_url`).
**Откуда.** `A/SoyMan_1shot/Rework/In_Audit_2.md` §10.

### О11 — Испытание на телефонах
**Вид:** проверка · **П3**
Два чарника и экспорт на настоящих телефонах: схема установки и носитель
экспорта. Не результатом «работает», а воспроизведением, если нет.
**Проверено 2026-10-22.** Не перепроверялось: была ли игра 27.09 этой проверкой — спросить владельца.
**Откуда.** `A/.scratch/oneshot-soyman/issues/02-mobile-validation.md`.

### О12 — Публичный каталог, аккаунты, восстановление
**Вид:** идея · **П3**
Состав публичного каталога, вход и восстановление доступа, хранение истории;
гостевой черновик без дублей. Частная `dist:full` — не публичный каталог;
личная база на внешний сервер не уезжает. Права на содержимое — «Выпуск», В25.
**Откуда.** `A/.scratch/oneshot-soyman/issues/04-public-service-design.md`.

**Помнить.** Справочник закреплён за персонажем: новая версия достаётся
только новым листам; менять — с новой `--catalog-version`.
